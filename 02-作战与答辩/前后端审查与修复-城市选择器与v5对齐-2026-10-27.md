## 2. P0：现场不可用（均已修复）

### P0-1 `file://` 打开时区划数据必失败
- 现象：链上读数正常（块高在涨），只有城市弹层报 `cn-cities.json` 加载失败；三级下拉全空。
- 根因：`ucOpen()` 用 `fetch("./cn-cities.json")`。用户是双击打开 `index-v5.html`（file://），
  浏览器按 CORS 拒绝 fetch 本地文件；与网络、文件是否存在都无关。
- 修复：新增 `cn-cities.js`（`window.CN_CITIES = <同一份 JSON>`，由 `cn-cities.json` 生成）；
  首次打开弹层时**动态注入 `<script src>`**（`ucLoadScript`）加载，file:// 与 http:// 都成立；
  仍保留 JSON fetch 作为 HTTP 兜底。没有把 137 KB 放进首屏（保持原来的懒加载）。
- 验证：file:// 打开 → 弹层 → 31 省可选 → 搜「义乌」出结果（截图存证
  `08-截图存证/2026-10-27-城市选择器与联调修复/修复后-file协议-城市弹层-2026-10-27.png`）。

### P0-2 加载失败后是死界面
- 根因：`catch` 只写一行「加载失败」就 return，下拉仍空、无重试。
- 修复：错误态给出**重试按钮**（`data-uc-retry` → `ucOpen()`），并说明缺的是哪个文件；
  弹层加 `role=dialog` / `aria-modal` / `aria-labelledby`；Esc、点遮罩关闭时同步 `aria-hidden`。
- 验证：在隔离目录里只放 `index-v5.html`（两套区划文件都缺）→ 弹层显示
  「加载失败：cn-cities.js；cn-cities.json HTTP 404」+ 重试按钮；把 `cn-cities.js` 放回后
  点一次重试即出现 31 个省与「选它：北京市 #110100」。测试目录已删除，未留产物。

### P0-3 搜索只认县名
- 根因：`ucSearch` 只遍历第三级 `a.name.includes(q)`；省名、地级市名、4 位市代码、6 位区划码都搜不到，
  与占位文案「县名/市名」不符；输入框也没绑回车。
- 修复：搜索覆盖省/市/县三级 + 数字码；按「完全匹配 → 前缀 → 包含 → 名称短」排序；
  最多 20 条并提示剩余条数；**回车选第一条**；无结果时给出可用写法。
- 验证：`金华`→金华市 #330700；`上海`→上海市 #310100；`湖北`→武汉等 17 个地级市；`330782`→义乌；
  `火星`→引导文案。

### P0-4 区划码与链上 regionId 错位（最隐蔽的一处）
- 根因：民政部表里地级市是 4 位（武汉 `4201`），链上 regionId 是 6 位（`420100`）；
  旧代码直接把 4 位码当 regionId，而且默认选中第一个区县（如 `420102` 江岸区）。
  另外「省直辖县级行政区划」（`4190/4290/4690/6590`）没有 6 位地级码；
  东莞/中山/儋州的下级是 9 位镇街码，也不是区划单位。
- 修复：新增 `ucCityCode`（4 位 + `"00"`）、`isProvDirectCity`（省直辖不给「整市」按钮）、
  `ucAreasOf`（只收 6 位区划；9 位镇街不进候选）；第三级默认「整个地级市」，区县作为可选第二条；
  `ucPick` 只接受 6 位码并给出错误提示。
- 验证：默认省=北京 → 选它 **北京市 #110100**（与链上 REGIONS 一致）；湖北 → 武汉市 #420100；
  河南 4190 → 只列济源市 #419001；广东 4419 东莞 → 只给 #441900，无镇街码。

## 3. P1：逻辑/口径错（均已修复）

### P1-1 真值 / 实时面板仍是旧 id 1..5（v3 口径）
- 现象：切「真值」后五城一览全是「—」；点真值柱子会把 `regionSel` 写成 `1`..`5`（无此 option → 空值），
  后续保费/看板错乱；实时面板同样点不动。
- 修复：新增 `REAL_CODE_BY_KEY` + `realRegionId()`，按城市 key 把快照 id 显式映射到 6 位区划码；
  `LIVE_COORDS` 的 key 改成链上 id；真值/实时两面板按 `REGIONS` 顺序出柱；
  所有 `|| 1` 兜底改成 `firstRegionId()`。
- 验证：真值模式 chips = 420100/310100/110100/440100/510100；五城一览有数（武汉 67mm…）；
  点「上海」→ `regionSel=310100` → 链上 `premiumOf(310100,24,0,0,1)=5.30 元`、阈值 50mm。

### P1-2 `|| 72` 兜底（v3 旧档）
- 根因：`refreshPremium` / `loadRegions` / `updateReadouts` 等处 `Number(hoursInput.value) || 72`；
  v5 只有 12/24，拿 72 去问 `entryThresholdOf` 会 revert，页面会显示兜底价并拦住投保。
- 修复：新增 `firstHour()` / `hoursNow()`，下拉未填好时取第一档，永不写死 72。
- 验证：rider/index-v5 报价均正常，无 CALL_EXCEPTION。

### P1-3 v5 被标成「v3 合约」
- 根因：版本探测只看 `entryThresholdOf(24)`，v5 也有这个 getter ⇒ `S.kind="v3"`；
  页首/配置区显示「v3 合约」，`ABI_SHAPE` 也用 v3 的字段数（恰好相同，掩盖了语义错误）。
- 修复：先探测 v5 独有的 `regionCount()` + `regions(420100)`，再退回 v3/v2；
  `ABI_SHAPE` 增加 v5；页首与配置提示按 `S.kind` 显示；`refreshPremium` 的版本分支改为
  「v2 走两参 / v3、v5 走五参 + entryThresholdOf」（v5 没有一参 `thresholdOf`）。
- 验证：页首显示「BOT Chain Testnet · chainId 968 · **v5 合约**」。

### P1-4 静态文案写「国标三级 50/75/100%」，合约 `TIER_COUNT=2`
- 修复：`#tierShow` / `#tierHint` 静态文案改为两档（50/75%）；meta 读到后再按链上档位数覆盖
  （保留三档分支只作防御）；`TIER_LABEL` 注释说明第三档在 v5 不可达。
- 验证：链上 `TIER_COUNT=2` → 页面显示「按国标两档 · 50/75%」。

### P1-5 退款/到期结算的保单显示成「等待生效」
- 根因：合约 `policyStatus()` 没有 refunded/settled 分支（v6 待修），退款后仍返回 `pending`；
  `index-v5` 的「我的保单」没有做覆盖（rider.html 已做）。
- 修复：按链上 `p.settled && !p.paid` 覆盖为 `refunded` / `settled`，并补两条说明文案与按钮禁用文案。
- 验证：逻辑与 rider.html 的既有修法一致（链上没有退款单可现场触发，走代码审查 + 语法门禁）。

### P1-6 未知事件会把事件流/台账整栏打空
- 根因：`iface.parseLog(log)` 对未知 topic 返回 `null`；两处代码直接取 `d.name` / `p.args`
  （`index-v5.loadEvents`、`console.ledgerLoad`），一条未来事件就会 TypeError，整栏读不出来。
- 修复：两处都加 `if (!d) continue;`；同时给事件纸带补了 `RegionRegistered` / `RegionActiveSet`
  的人话（v5 新城市开通/停售，之前只显示事件名）。
- 验证：事件流 20 条正常；console 台账 2 条 + `poolBalance` 逐分一致。

### P1-7 骑手端「复制凭证」状态为空
- 根因：`POLICY_CACHE[id] = p` 只存保单，复制时 `certText(id, p, "")` 传空状态。
- 修复：缓存改为 `{p, st}`（`st` 是已覆盖 refunded/settled 的状态）；复制、理赔列表、申诉共用同一份；
  `loadClaims` 也按 settled 覆盖状态（之前退款单会显示「冷静期」）。

### P1-8 未开通城市的第六片「能点但一定失败」
- 现象：选了链上未注册的区划（杭州 `330100`），城市片仍可点；点下去走 `premiumOf` → revert
  「region not available」，页面显示兜底价与错误提示；看板小字却说「第六柱暂不显示」，两处不一致。
- 修复：`loadRegions` 读到 `regions(code).active === false` 时禁用该城市片（`disabled` + 原因 title），
  补 `.chip:disabled` 样式；链上一开通（下一轮轮询）自动恢复；看板仍只画已开通城市。
- 验证：选杭州 → 片禁用 + 提示「尚未开通保单…」、第六柱不出现、当前选择仍是武汉 `420100`、保费正常。

## 5. 合约侧只读审查（未改链上；留给 v6）

1. **`policyStatus()` 缺 refunded / settled**：退款后仍 `pending`，到期结算后仍 `active/expired`。
   前端已按 `settled && !paid` 覆盖显示；根治要 v6 加状态。
2. **`claim()` 要求 `now <= endTime`，而 `_judge()` 没有窗口校验**：判定若在到期后才上链，
   这张单永远赔不出去（钱不是被结算吞掉，是到期那一刻闸门关死）。`keeper.js` 已把这个风险写在注释里。
   建议 v6：`claim` 允许「已有判定」的过期单领取，或 `_judge` 强制在 `effectiveFrom..endTime` 内。
3. **`_judge` 一次性且无时间窗**：过早/过晚的判定都会把保单锁死（不能重判、不能申诉上链）。
   运营侧约束：`submit-judgement.js` 已有重复判定守卫，但没有窗口守卫；
   建议在脚本里补「未到 effectiveFrom / 已过 endTime 不提交」，或 v6 加窗口 require。
4. **批发参数未实现**：`premiumOf(riderTier, channel, count)` 忽略后三个参数，`buyFor` 要求 `count==1`
   （e2e 已把这条钉成 v5 已知限制）。平台批量只能逐人一单，`batch-buy.js` 与 console 均按此实现。
5. **累计喂价的迟到效应（设计性风险）**：判定用「累计读数差」，若投保后第一次喂价迟到，
   会把投保前已下的雨算进增量。当前 4 小时计划任务 + `MAX_FEED_AGE=24h` 把窗口压到很小；
   演示前应确认喂价新鲜（rider 页已有 20h/24h 提示）。
6. 资金安全面：`claim` 先改状态后转账、`refundPolicy` 同理，ERC20 是自家 RainToken，无重入面；
   `withdrawPool` 有 `reserveOf` 下限；`reserveOf = max(reserve, openExposure)` 保守。未发现新增高危。

## 6. 功能缺口与可扩展（评估结论）

| 方向 | 现状 | 建议 |
|---|---|---|
| 城市可用性提示 | 选完城市后由链上 `regions(code).active` 告知；选择列表里看不出哪些已开通 | 弹层里对 6 个已注册码打「已开通」标签（需一次批量 `eth_call`，可缓存） |
| 搜索 | 名称/区划码；无拼音、无高亮 | 接 pinyin 首字母（数据需另生成），或只做结果高亮 |
| 无障碍 | 弹层有 role/aria/Esc/回车；无焦点陷阱 | 若要在评审现场演示读屏，再加 focus trap |
| 前端门禁 | 已有语法/转义 + ABI 同步 + 城市数据；没有 UI 行为断言 | 给 `check-ui.js` 加 index-v5 的 DOM/区划码断言（现有 check-ui 只覆盖 index.html） |
| 批量投保 | console 逐人 `buyFor(...,1)`，逐笔等待 | 合约支持后改 `count`；否则保持逐笔并在 UI 显示进度 |
| 首屏体积 | ethers 526 KB + 页面 257 KB；区划 137 KB 懒加载 | 按需拆 ABI/ethers 是 P1，风险大，维持现状 |
