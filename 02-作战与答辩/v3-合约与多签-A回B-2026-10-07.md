## 2. 接口变更（**破坏性，B 侧脚本要跟着改**）

1. `submitJudgement(policyId, decision, confidence, sources, `**`rainfallAtJudgement`**`, inputHash, outputHash, modelVersion)` —— 新增第 5 个参数（A-5④ 判定快照）。`JudgementSubmitted` 事件多一个字段 ⇒ **topic0 与 v2 不同**，按旧 topic 过滤的老脚本会读不到。
2. `premiumOf(uint8 regionId, uint256 hours_)` → **`premiumOf(uint8 regionId, uint256 hours_, uint8 riderTier, uint8 channel, uint256 count)`**；不可售格 **`revert("not offered")`**（不回退）。**2 参重载保留**（= `premiumOf(regionId, hours_, 0, 0, 1)`），所以只读旧页面不会被硬断。
3. `hoursAllowed` = **{12, 24}**（v2 是 24/48/72）；`thresholdOf(uint256 hours_, uint8 tier)` 改成**国标查表**：12h → 30 / 70 mm，24h → 50 / 100 mm（GB/T 28592—2012 表 1）。`thresholdMm` 记的是**最低档（暴雨线）**，`entryThresholdOf(hours_)` 是它的便捷读法。
4. `tierBps` **两档**：5000 / 7500（暴雨 50% / 大暴雨 75%）；`TIER_COUNT = 2`。
5. `MIN_PREMIUM` **0.00002 ether**（A-5①，降 10 倍；你那边批量价最低 0.00006）。
6. `buyPolicy` 语义不变（`payer = rider = msg.sender`）；新增 **`buyFor(beneficiary, regionId, hours_, riderTier, channel, count)`**（A-6，`payer = msg.sender`、`rider = beneficiary`）。
7. 新增 `refundPolicy(policyId)`（冷静期内退保，退款给 `payer`）、`openPoliciesOf(address)`（只计未结清，O(1)）、`setPricingModule(address)`、`pricingModule()`、`PolicyRefunded` / `PricingModuleSet` 事件。

## 3. 五维定价模块怎么接（A-5②）

V3 内置 `interface IPricingV3 { function quoteOrZero(uint8 regionId, uint256 hours_, uint8 riderTier, uint8 channel, uint256 count) external view returns (uint256 price, bool sellable); }`。

- `pricingModule == address(0)` ⇒ 走 v2 的本地网格口径（`premiumGrid` / `aiPremium` / `MIN_PREMIUM` 兜底），**现有演示不受影响**；
- operator 调 `setPricingModule(<你的 PricingV3 地址>)` 后，`premiumOf` / `quoteOf` 直问模块；模块没配的行按 `sellable = false` 处理（`premiumOf` 会 revert `not offered`）。
- 本轮的测试只用一个**桩模块**验证了「接上 / 换掉 / 摘掉」三条路径；**没有在真链部署你的 `PricingV3.sol`**（用户明确要求先不往 677 部署），所以「真合约 + 真 60 格 payload」这条组合等你那边的部署动作。

## 4. 一条链上取舍要你确认（`count` 的含义）

`buyFor(... count)` 里 **链上只按单元成交**：`_buy` 有 `require(count == 1, "on-chain buys are per-unit (count must be 1)")`。原因：N ≥ 10 的批量价是「平台团体」档，而骑手维度有 **敞口闸**（`MAX_OPEN_EXPOSURE_PER_RIDER = 0.02 ETH`）与 **限购闸**（3 笔未结清），一次给同一受益人写 N 份必然撞闸；把闸放开又不是我们想在生产里开的口子。
⇒ **`count` 只作为报价维度**（`premiumOf(..., count)` 可用来出对账单价格），链上结算走「逐人单笔」。若你更希望链上一次开 N 笔（N ≤ 100，受益人各不相同），那是另一个函数（`buyBatch`），要单独立项 —— 需要你确认这符合你的 B2B2C 结算口径。

## 5. A-4 多签（`OperatorMultisig.sol`）

- 构造 `OperatorMultisig(address[] owners_, uint256 threshold_)`，守卫：owners 非空 / threshold ∈ [1, owners.length] / 无零地址 / 无重复。
- `submit(target, value, data)`（提交者自动 1 票，够票即执行）、`confirm` / `revoke` / `execute`；只读 `getOwners` / `threshold` / `txCount` / `getTx` / `isConfirmed` / `isOwner`；`receive()` 可收款。
- 治理三件套 `setThreshold` / `addOwner` / `removeOwner` 全是 **onlySelf**（多签自己调自己，无 owner 直连后门）。
- **执行失败整笔回滚**，并把目标合约的 revert data **原样冒泡**（排障可读）。
- **切换 operator 零改动**：`RainDeliveryInsuranceV2.sol:419 transferOperator(address next) external onlyOperator` 已存在 ⇒ 部署多签后由现 operator 调一次 `transferOperator(<多签>)` 即可；之后**原单私钥单独发 `updateRainfall` 会被 `not operator` 拒**（这条就是「真换了」的证据，e2e 里已覆盖）。
- 诚实缺口：**没在任何真链部署过**、没做 gas 估算/审计；`threshold = 1` 只间接走过；`removeOwner` 用 swap-and-pop **会打乱 `getOwners()` 顺序**；多签自己作 owner 的嵌套与超大 calldata 未测；不做 payload 去重（同 Gnosis Safe，靠 `txId + executed`）。
