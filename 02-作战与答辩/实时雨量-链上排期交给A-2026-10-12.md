## 2. 要 A 拍板的三条路

**(a) 多签喂价 + 定时提醒（当前唯一零改动可行的路）**
值守人按提醒跑一次喂价，由 2/3 多签执行。安全性最好，依赖人守时。
一键刷新：`cd 04-脚本 && npm run refresh`（同值重喂，只把 `lastFeedAt` 推到当下，累计值一动不动）。

**(b) 独立 feeder EOA + GitHub Actions 定时**
`transferOperator(address next) external onlyOperator`（`V3.sol:569`）允许把 operator 交给一把专用 EOA，
之后 workflow 用 `on.schedule` + repo secret 自动喂价。
代价要说清：**operator 是单签全能权限**（提池 `withdrawPool:612`、改价、暂停、设准备金都在它手上），
把 operator 交给一把放在 CI secret 里的热钥，是把多签换成了单点。

**(c) 不排期，只落运维手册**
明确写「演示前 24 小时内必须手工喂一次」，并把这一步塞进演示流程清单。

**建议**：先 (c) 保命 → 再评估 (a)；(b) 只在「能接受 operator 单签」时才做。
无论选哪条，都**不要改已部署的合约源码**（会破掉「源码 ↔ 字节码 ↔ 链上」的证据链）。

1. `cd 04-脚本 && npm run status` 每一行都显示「基线 剩 Xh」且 `X > 0`；
