# 2 核 2G / 50G 盘 · 部署手册与容量实测（2026-10-27）

> 结论先说：**2C2G 跑得动，而且很宽裕**。真正卡住你的不是 CPU 和内存，是 Open-Meteo 免费档的 **1 万次/天** 天气额度。
> 本文所有数字都是本机实测（Node v24.20.0，同一套脚本、同一条链 968、同一份 122 区划注册表），不是拍脑袋估的。

## 二、轮询次数（这才是真正的天花板）

### 2.1 喂价：每轮 122 次天气请求

Open-Meteo 免费档限额：**600 次/分 · 5,000 次/时 · 10,000 次/天 · 300,000 次/月**。

| `--watch=` | 轮/日 | 天气请求/日 | 占日额度 | 占月额度 |
|---|---|---|---|---|
| 15 分 | 96 | 11,712 | **117.1%** ❌ 爆 | 117.1% |
| **30 分** | 48 | 5,856 | **58.6%** ✅ | 58.6% |
| **60 分** | 24 | 2,928 | **29.3%** ✅ | 29.3% |
| 120 分 | 12 | 1,464 | 14.6% | 14.6% |

理论上限：**82 轮/日**（10,000 ÷ 122），即最快约 **17.6 分钟一轮**；按小时限算是 41 轮/时 → 约 35 分钟一轮。

**采用 `--watch=30`**（全仓统一口径，与 Windows 计划任务 `RainProof-Feed` 的 `PT30M` 一致）：48 轮/日、5,856 次/日，占免费额度 58.6%。合约 `MAX_FEED_AGE = 86400 s = 24 h`、脚本 `REFRESH_HOURS = 20`，30 分钟一轮留了 48 倍保鲜余量，连挂 10 轮也不会让任何区划过期。想再省额度才降到 `--watch=60`（29.3%）。

> ⚠️ 别用 `--watch=15`：117% 日额度，跑到第 20 小时就被限流，而且限流是**静默降级**——你只会看到「拉取失败」，看不出是额度问题。

### 2.2 keeper：每轮 2 + n 次 RPC（n = 保单数）

| `--interval=` | 保单数 | 轮/日 | RPC 次/日 | 平均 QPS |
|---|---|---|---|---|
| 15 s | 1 | 5,760 | 17,280 | 0.20 |
| 15 s | 10 | 5,760 | 69,120 | 0.80 |
| 15 s | 100 | 5,760 | 587,520 | **6.80** |
| 30 s | 10 | 2,880 | 34,560 | 0.40 |
| **60 s** | 10 | 1,440 | 17,280 | **0.20** |
| 60 s | 100 | 1,440 | 146,880 | 1.70 |

`keeper.js` 默认 `INTERVAL = 1800`（30 分钟，与 feeder 同口径）。理赔判定粒度本来就由 `MAX_FEED_AGE`/结算窗口决定，30 分钟扫一次够用且几乎不产生 RPC 压力；只有做演示冲刺、需要「刚到期就赔」时才临时降到 `--interval=60`（1,440 轮/日）。

## 三、2C2G 装得下什么

### 3.1 内存

```
nginx（静态站）              ~10 MB
keeper.js 常驻               ~68 MB
feeder 每 30 分钟起一次       ~87 MB（跑完退出，不与 keeper 叠加）
────────────────────────────────────
峰值                          ~165 MB / 2048 MB  →  8%
```

**结论：内存完全不是问题**，2G 里还剩 1.8G。就算再挂个 SQLite、再开个备份脚本也够。

### 3.2 CPU

feeder 一轮 96 s 里只烧 **2.14 s CPU**（2.2% 单核），其余时间全在等 122 个 HTTP 响应。keeper 平时就是 sleep。**两个核基本闲着**。

### 3.3 磁盘

部署 19 MB + Node 24 运行时约 100 MB + 日志/留痕增长。留痕每天约 **33 KB × 24 轮 ≈ 0.8 MB/日**，`raw/` 目录自带 **50 MB 上限**（超了停存并告警）。50G 盘按这个速度能写 **几十年**。

## 四、部署清单

### 4.1 要传的文件（≈ 19 MB）

```

├── 05-演示站点/           1.83 MB   静态站（index-v5 / rider / console / verify-v5 + ethers + cn-cities + evidence）
├── 06-核验台单文件/       0.05 MB   单文件核验台（可不用）
├── 03-合约/               0.50 MB   ABI（keeper/feeder 读 ABI 用）
├── 04-脚本/               0.67 MB   源码；node_modules 不要传，服务器上 npm i
└── 09-AI判定留痕/         0.33 MB   判定留痕（可选，演示时给人看证据链）
```

**不要传**：`.git`（183 MB）、`07-测试工具/node_modules`（359 MB）、`04-脚本/node_modules`（205 MB）、`08-截图存证`（11 MB，本机留档即可）。

服务器上只需装两个包：

```bash
cd 04-脚本 && npm i --omit=dev    # ethers + dotenv，16 MB
```

### 4.2 三个进程

```bash
# 1) 静态站
nginx -c /etc/nginx/nginx.conf      # root 指向 05-演示站点

# 2) keeper：发现可赔就替骑手领
cd 04-脚本 && node keeper.js --interval=60 --v5

# 3) feeder：每 30 分钟喂一轮价（先补 confirm 钱包 gas，再喂；`;` 不用 `&&`）
cd 04-脚本 && node fund-v6-ops-gas.js --send ; node push-rainfall-v6.js --watch=30 --send
```

**为什么先补 gas**：批量投票的两票各约 0.064 BOT（20 gwei × ~3.2M gas），confirm 钱包一旦低于一批的量，整个运行会以 `insufficient funds` 结束、链上喂价开始变旧。2026-10-30 就是这么中断了 13 小时。补气成本由部署钱包出，阈值 0.5 BOT（够 7 批），余额高于阈值时不发交易。

两个 Node 进程都用 systemd 拉起（`Restart=always`、`RestartSec=10`），日志进 journald。

### 4.2b 上线后一条命令体检

```bash
cd 04-脚本 && node preflight.js        # 全绿退出码 0；有 ❌ 退出码 1
```

查七类：文件齐不齐（含 `cn-cities.js`、`solvency-mc-inline.js`、`WUHAN_EVIDENCE_TEXT` 三个 file:// 兜底）、注册表条数与重复码、链 id / `regionCount` / `poolBalance` / `nextPolicyId` / `openExposure`、`premiumOf(420202,12|24)`、122 个区划的最老喂价与剩余小时（超 24h ❌、剩 <4h ⚠）、三个 owner + deployer 余额（<0.15 BOT ❌，两票 gas 保底 20 gwei × 3.2M ≈ 0.064 BOT/批）、计划任务状态（仅 win32）。`--json` 出机器可读，可直接喂给监控。
换机器部署完、每次改 `.env` 或换 RPC 后都跑一次；比盯日志快。

## 五、真正会咬人的三件事（按概率排序）

1. **Open-Meteo 免费档是「非商用」许可**。比赛演示可以，真卖保单就得买 Standard（1M 次/月）或自建。这条写进风险页，别等评委问。
2. **公共 RPC 会限流**。`rpc.bohr.life` 是公共节点，keeper 上到 6 QPS 就危险。要么把 `--interval` 拉到 60，要么自建节点 / 用 `11-节点代理-vercel` 那套代理。
3. **喂价静默失败**。脚本已经做了「拉取失败必须打印 + 记进 skipped」，但**没人看日志就等于没有**。建议加一条 `journalctl -u feeder --since 1h | grep -c 拉取失败` 的日检，非零就告警。

## 六、一句话结论

| 问题 | 答案 |
|---|---|
| 2 核 2G 装得下吗？ | **装得下，只用 8% 内存、2% CPU、19 MB 磁盘** |
| 瓶颈在哪？ | **天气 API 额度**（1 万次/天）+ 公共 RPC 限流，不是机器 |
| 推荐配置 | `feeder --watch=30`（58.6% 额度）+ `keeper --interval=1800`（30 分钟一轮，RPC 压力可忽略） |
| 要升级吗？ | 演示/小规模运营不用。区划破 300 或保单破千再考虑 4C4G + 自建节点 |
