## 1. 项目目标与定位

**一句话**：把「暴雨天骑手跑不了单、当天收入清零」这件事，变成「雨量过阈值 → 自动赔付」，且全过程可被第三方独立复算。

**三个技术支点（对外叙事也靠这三条）**
1. **国标阈值**：GB/T 28592—2012 只有 12h / 24h 两个时段 → 档线 12h: 30/70mm、24h: 50/100mm；赔付比例 50% / 75%（满额 100 元）。
2. **AI 只验真，不判赔**：三机构数值预报模型（ECMWF/GFS/ICON）交叉核验数据可信性；赔付与否由**确定性规则 + 链上读数**决定，同一份输入必得同一结论。
3. **可验证**：每笔喂价/判定把输入哈希与输出哈希写链上；任何人拿留痕 JSON 重跑 `replay-judgement.js` 得到逐字节相同结果。

**商业模式**：B2B2C——平台/众包服务商付费，不指望骑手自掏。人民币定价表：零售 1.1–8.8 元/份，平台团体批发 1 元级/份（`保险创业赛-2026/02-定价-人民币口径/`）。
**注意（2026-10-26 实测）**：v5 的 `premiumOf(regionId,hours,riderTier,channel,count)` 对 riderTier / channel / count **一律忽略**，六种组合返回同一价（上海 12h=420 分、24h=530 分）。即「平台批发 1 元级/份」目前是**商业条款，未写入合约**（`MIN_PREMIUM=100 分` 只是下限，不是实现）。对外讲价时说清：演示按零售价结算，批发价需 v6 才能实现。

**注意（2026-10-26 实测，v6 必修）**：`_judge()` **不校验窗口是否已结束**（只查 policy 存在、无既有 judgement、未 settled、`rainfallAtJudgement` 在 `[rainfallAtBuy, rainfall[regionId]]` 区间内），而 `_judge` 又要求 `!j.exists` ⇒ **窗口开着时提交的 DENY 会把这张保单永久锁死**，之后即使雨量越线也判不了了。`policyStatus()` 在窗口内仍按「雨量是否达标」显示 `active`（不看 judgement），所以页面上看不出保单已被判死，直到 `endTime` 之后才变 `expired`。演示时先等窗口结束再判（2026-10-26 20:02 我们对保单 #0 提前判了 DENY：当时三家模型对余下 5.4h 的窗口区间都算 0mm，风险可控，但这是运气不是设计）。v6 应把 `block.timestamp >= p.endTime` 写成 `_judge` 的前置条件。

**当前阶段**：技术栈已完整可跑（968 演示网），正在准备「分子实验室-2026 大学生保险模拟创业大赛」（报名截止 **2026-10-31 17:00**）。比赛只交计划书+答辩，不要求链。

```
                    ┌──────────────── 前端（零构建静态页，无后端）────────────────┐
                    │ index-v5.html  看板+投保（第六柱=用户自选城市，省市县三级）  │
                    │ rider.html     骑手端：投保/保单凭证/理赔记录/申诉          │
                    │ console.html   平台端：池子/费率/事件/批量投保/对账/台账/偿付│
                    │ verify-v5.html  v5 核验台：8 条断言逐条自证（主 CTA 指向这里）  │
                    │ verifier.html + 06-核验台单文件   v3/677 历史核验台（离线可用）  │
                    └───────────────┬─────────────────────────────────────────────┘
                                    │ ethers v6 UMD，只读走 RPC；写操作走钱包签名
     ┌──────────────────────────────▼───────────────────────────────┐
     │ 链上（BOT Chain 968）                                          │
     │  RainDeliveryInsuranceV5  承保/喂价/判定/赔付/敞口/区域注册      │
     │  RainToken (RDROP)        计价代币（owner=多签，可铸演示资金）  │
     │  OperatorMultisig 2/3     治理：喂价/判定/定价/铸币/停售        │
     └──────────────────────────────▲───────────────────────────────┘
                                    │ 两票 submit+confirm（自动执行）
     ┌──────────────────────────────┴───────────────────────────────┐
     │ 运营脚本（Node，04-脚本/）                                     │
     │  push-rainfall-v5.js  拉三模型→增量闸门→批量喂价（--watch 轮询）│
     │  ai-collect/ai-judge/submit-judgement   证据快照→判定→上链     │
     │  keeper.js            免权限自动理赔                          │
     │  notify.js            巡检告警（可推企业微信）                 │
     │  warning-watch.js     暴雨预警→停售建议（出两票命令）          │
     │  replay-judgement.js  判定一键重放（可复算）                   │
     │  reprice-review.js    定价季度回溯                            │
     └──────────────────────────────────────────────────────────────┘
              旁路 A：09-AI判定留痕/（快照+判定+原始报文 raw/ + sha256）
              旁路 B：10-金融与定价/（11 年实测精算 + 定价引擎 + 蒙特卡洛）
```

**关键设计决策（接手前必须理解）**
- **regionId = 民政部行政区划码（uint32）**，不是 1..5 自增号。武汉=420100、上海=310100、北京=110100、广州=440100、成都=510100、黄石港区=420202（县级）。湖北 118 区划已全量开通。前端下拉框的 value 是 1..5，**必须经 `CITY_CODE` 映射**再传合约——这是历史上最常见的 bug（见 §11）。
- **金额单位是「分」**：链上 880 = 8.80 元。前端 `fmtEth()`（名字历史遗留）已改为 `w/100` 显示元。
- **降雨是绝对累计**：`rainfall[code]` 存「自 RAIN_EPOCH（2026-10-01）起累计 mm」，单调不减；保单存投保当刻快照 `rainfallAtBuy`，赔付算**增量**。
- **判定快照**：`judgements[id].rainfallAtJudgement` 是判定那一刻的读数，`claim` 按它算增量（不是申请赔付那一刻），防窗口滚动磨掉应赔保单。

## 6. 关键流程与数据流

### 6.1 投保（rider.html）

```
选城市(1..5) + 时长(12|24)
 → CITY_CODE[选择值] 得到区划码          ← 必须映射！否则查无此区域
 → premiumOf(code, hours) 读链上保费（分）
 → allowance(用户, 合约) ≥ 保费?
     是 → 直接 buyPolicy(code, hours)（单笔）
     否 → 勾了「大额授权」则 approve(保费×100)，否则 approve(保费)；再 buyPolicy
 → 链上 checks: region active / 非停售 / 喂价新鲜(≤24h) / 未超限购(3 笔) / 未超敞口(20000 分)
 → 链上扣 RDROP + 记 rainfallAtBuy 快照
 → 前端刷新保单/凭证/理赔区
```
**注意**：v5 的 `coolingPeriod = 259200`（**3 天**，实测）。买完状态是 `pending`，3 天后才 `effectiveFrom` 生效，再进入 12/24h 窗口。**演示要即时生效需两票把 coolingPeriod 设为 0**。

### 6.2 喂价（`push-rainfall-v5.js`）

```
每城：拉三模型逐小时降水（past_days=30, forecast_days=1）
 → 窗口 = (上次喂价时刻, min(现在, 数据末端)]
 → 三模型窗口增量 → 中位数；≥2 个落在 ±max(2.5mm, 5%中位) 内才算一致
 → 一致：候选 = 链上现值 + round(中位增量)（单调，绝不倒退；无增量且喂价>20h 则同值保鲜）
    不一致：只打印 rejectFeed 两票命令，不自动喂
 → 批量 updateRainfallBatch（**走两票**，脚本 --send 时用 B1 提交 / B2 确认）
 → 轮末写 09-AI判定留痕/v5-feed-trace-<时刻>.json（含各城三模型值 + raw 文件名 + sha256）
```
`--watch=30` 常驻轮询（30 分钟一轮，与计划任务 `RainProof-Feed` 的 `PT30M` 同口径）。注册表 122 个区划，多数轮次无增量（真实状态：这几天没下够雨），只有增量 ≥2.5mm 或喂价超 20h 的区划才进批。

### 6.3 判定（`ai-collect` → `ai-judge` → `submit-judgement`）

```
ai-collect <id>   拉三模型证据 → 09-AI判定留痕/snapshot-policy<id>.json（含 inputHash）
ai-judge <id>     规则 R1–R5 → judgement-policy<id>.json（decision/confidence/metrics/reasons + outputHash）
submit-judgement  重算核对后 → 两票 submitJudgement(...)（含 rainfallAtJudgement 快照）
```
**confidence 是「多源一致性自评」**（三模型落在中位容差内比例 + 与链上读数相符程度），**不是统计置信区间**。前端已加「自评口径」徽标；对外话术不要说成"95% 置信度"。

### 6.4 理赔（`keeper.js` / 任意人 / 前端）

```
claim(id) 无需权限（payable 前需 approve 无；v5 走 RDROP）
 条件：存在 / 未赔 / 未结算 / 已生效 / 未过期 / 有判定 / decision==PAY / confidence≥60 / 增量≥档线 / 池子够
 → 按 tierBps 转 RDROP 给保单 rider（档位 50%/75%）
settleExpired(ids) 也无权限：到期未赔的保单了结、回收敞口
```

### 6.5 治理（所有 onlyOperator 动作）

```bash
# 读状态
node 04-脚本/multisig-ops.js status
# 通用两票（B1 提交 → B2 确认自动执行；confirm 到阈值即 _execute，无需单独 execute）
```

合约语义（`OperatorMultisig.sol`）：`submit` 提交者自动计 1 票；`confirm` 达阈值立即执行；`removeOwner` 有 `owners-1 ≥ threshold` 护栏（顺序反了永久锁死）。

## 11. 常见易踩坑点（都是本仓库真实发生过的）

1. **区划码 vs 下拉框值**：前端 `<select>` 的 value 是 1..5，链上是 420100 等。**每一处读链都必须 `CITY_CODE[+sel.value]`**。历史上 5 处漏映射：雨量读成 0、报价 revert、批量投保报错、保单城市名 undefined、投保必挂。
2. **声明与调用点改名不同步**：v5 迁移时把 `v4.xxx` 全改成 `v5.xxx`，但 `const v4 = new Contract(...)` 没改 → 页面**所有**链上读取静默失败（表现为"连接失败/—"，不是报错）。凡批量改名，务必同时改声明，并在浏览器里 verify。
3. **`npm test` 全绿 ≠ 页面能用**：门禁只做静态/离链检查（语法、DOM id 存在、契约数值）。**改前端必须 reload 实看**。
4. **弹层/浮层被父容器 `display:none` 吃掉**：`.ucpop` 住在投保分区里，在看板页点开时矩形全零（"点了没反应"）→ 打开时 `document.body.appendChild(pop)`。
5. **`position:fixed` 必须给坐标**（`top/left` + `transform` 居中），否则停在文档流原位、可能滚出视口。
6. **容器级点击处理器会吞子按钮**：`#rainMode` 的标签切换 handler 用 `closest(".f")`，把放进去的按钮当成"第四个标签"并隐藏所有看板 → 子按钮用 `btn` 类而非 `f` 类，并 `stopPropagation`。
7. **变量名错位**：`console.html` 的 provider 叫 `p`（不是 `provider`）；`rider.html` 有 `$`/`toast`/`yuan` 全局；`esc()` 只在 console 里，rider 没有。
8. **TDZ**：函数内引用 `const CODES` 但该 const 声明在同文件的更后面 → 初始化即抛 `Cannot access before initialization`，整块面板空白。用自含映射或把声明前移。
9. **行尾差异**（实测）：`index.html` / `index-v4.html` / `index-v5.html` / `verifier.html` 是 **CRLF**；`rider.html` / `console.html` 是 **LF**。写补丁脚本时按文件实际行尾归一（`s.includes("\r\n") ? "\r\n" : "\n"`），否则多行锚点匹配不到。
10. **改文件一律用「锚点预检 → 断言替换 → 写盘前语法门禁」**：本仓库的补丁脚本都是这个模式（`04-脚本/_patch-*.js`），断言失败即中止不写盘。直接 `sed -i`/正则盲改会出事。
11. **bash 里的反引号**：Git Bash 中 `` ` `` 会被当命令替换执行，污染写入内容（曾把命令输出嵌进运营手册表格）。写文件用 Node 脚本或 heredoc 且用 `'EOF'` 引号。
12. **`forward_days=0` 类时效坑**：`forecast_days=0` 只能拿到"昨天的数据"（喂价器一度看不到今天的雨）。窗口右端要按数据实际末端封顶。
13. **模型键前缀**：Open-Meteo 返回的键是 `precipitation_ecmwf_ifs025`，不是 `ecmwf_ifs025`。取错 → 窗口恒空 → **所有城市被误判"三模型分歧"**（曾长期如此，因禁自动写链未污染链上）。
14. **RPC 限流**：`rpc.bohr.life` 频繁调用后会变慢（实测单次 0.5–2.6s）甚至间歇 000。脚本要有重试（`withRetry`），前端要有降级（缓存上次读数 + 30s 轮询 + 可见性感知）。
15. **本地静态服务会掉**：终端关掉 `python -m http.server` 就停，浏览器显示 `chrome-error://chromewebdata/`、页面全白、`$` 未定义。重启服务即可，别误判为代码坏了。
16. **多签顺序**：换主必须 `addOwner` 全做完再 `removeOwner`；`removeOwner` 会校验剩余 owner ≥ threshold，顺序反了**永久锁死**合约。用 `multisig-ops.js handover`（脚本强制顺序 + 锁死预检）。
17. **`submit` 自带一票**：提交者不能再 `confirm` 同一笔（会 revert `already confirmed`），第二票必须换另一把 owner 钥匙。
18. **不要用 `sepolia.otterscan.io`**（后端已挂，永远转圈）。核验用 `06-核验台单文件` 或 `scan.bohr.life`。
