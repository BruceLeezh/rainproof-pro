## 1. 必须改（合约层）

| # | 病灶（现状） | 修法 | 连带影响 |
|---|---|---|---|
| **A1** | **保费与时长解耦**：`premiumOf(uint8 regionId)`（`:125`）没有时长参数，而 `buyPolicy` 又 `require(msg.value == premiumOf(regionId))`（`:134`）→ 口子焊死，6h 与 72h 同价（**期限套利 88–192 倍**，P1-14） | `premiumOf(uint8 regionId, uint256 hours)`；只卖 **24/48/72 三档**；每档一个保费，**加保费地板**（依据：一笔真链投保 gas = 0.00046 ETH，而 6h 档公平保费 0.000009 = 它的 1/51 → 短窗口档在 L1 上收不回成本） | `04-脚本/set-premium.js` 从 5 个值变成 **15 个值**（`--hours=N --apply` 已支持）；演示页 `premiumOf` 调用要带 hours；`定价-时长差异化设计.md` 的表直接可用 |
| **A2** | **阈值与窗口不匹配**：`THRESHOLD = 50`（`:22`）是常数，而窗口 1–72h 可调 → 50mm 只有配 24h 窗口才等于国标暴雨（P1-2），72h 那条线实际相当于 150mm | 阈值随窗口缩放：`thresholdOf(hours)` —— 24h→**50mm**（= `GB/T 28592-2012` 暴雨下限）、72h→**150mm**（或 `50×h/24` 线性）；`Policy` 结构**增存 `thresholdMm`**，`claim`（`:251`）、`policyStatus`（`:383`）、`rainfallDuring`（`:348-351`）三处全部改成读保单自己的阈值 | 演示页「触发线」刻度（`min(1, v/(thr*2))`）要改成读保单/区域的阈值；`check-ui.js` 第①段断言要同步；看板脚注 |
| **A3** | **不限购**：`buyPolicy`（`:131-147`）对同一地址买几张没有任何限制，`_byRider`（`:147`）只是索引 → 一个人 0.0008×5 张（0.004 ETH）就能拿走 0.0512 的池子 = **12.5 倍**（P1-19/P1-20） | `MAX_POLICIES_PER_RIDER`（如 2）+ `MAX_PAYOUT_PER_RIDER`（按日收入倍数，如 ≤3×赔付额）；两个 require 即可，`_byRider` 是现成索引 | `e2e_contract.js` 加反向断言（超限必 revert）；红线表补一句 |
| **A4** | **即刻生效**：`:141` `startTime = block.timestamp`、`:142` `endTime = startTime + hours` → 雨已落地但未喂价时买票 = 白赚（P1-19 的真洞） | 二选一（建议**都做**）：① **售前截止**：保单只保「某个日历窗口」，且**必须窗口开始前买**（事后买在定义上消失）② **`t+3` 冷静期**：`effectiveFrom = block.timestamp + 3 days`，`endTime = effectiveFrom + hours`，期间状态为 `pending` | 状态机多一个状态 → 演示页 `label` 映射、`policyStatus` 字符串、`claim` 的 `require(block.timestamp <= p.endTime)` 都要改；`hoursInput` 三档要配合 window 口径 |
| **A5** | **`sources` 恒为 0**：`submitJudgement` 签名（`:209-211`）没有 `sources` 参数，`:220` 写死 `sources: 0` → 链上读到的采信源数永远是 0（P1-13） | 签名加 `uint8 sources`，`JudgementSubmitted` 事件加 `sources` 字段 | ABI 重生成 → 演示页 AI 判定卡（`05-演示站点/index.html` 的 `aiLine`）**终于可以显示"采信 3 个源"**；核验台 `EVENT_ABI` 与 `eventSummary` 同步 |
| **A6** | **`reserve` 没有自动规则**：`:46` 只有一个人工 `setReserve`（P1-12） | 加只读视函数 `reserveOf()` = 在保敞口 × 赔付额 × 比例；`setReserve` 不得低于该值（或直接由它推导） | `fundPool` / `withdrawPool` 的守卫从 `reserve` 改成 `reserveOf()`；e2e 的「准备金不能超过余额」断言要补一条 |

| **A9** | **险种写死**：`:20-24` 五个 `constant`（PREMIUM/PAYOUT/THRESHOLD/MIN_HOURS/MAX_HOURS）都在合约层 | 提成 `struct Product { payout; thresholdPerDay; minHours; maxHours; premiumBase; }` + `productId`；事件带 `productId` | 为高温/大风/空气污染（P2-6）铺路；AI 层不用改（同数据源）；但**A1/A2/A7 的改动要在 Product 里表达**，所以 A9 最好和 A1–A7 一起设计 |

## 6. 不做 v2 的代价（对照，供你们拍板时看）

| 不做 | 后果 |
|---|---|
| A1/A2 | 期限套利 88–192 倍、阈值口径与国标不一致 → 专业评委会当场问倒 |
| A3/A4 | 池子可被一个人两次交易拿走 12.5 倍 → 这不是"风险"，是**产品有洞** |
| A5 | 链上 `sources` 永远 0 → "三模型交叉核验"这句缺链上证据 |
| A7/A9 | 只能做暴雨一个险种、只能二元赔付 → 赛道结合度的"可扩展性"只能靠嘴讲 |
| A8 | 法理上仍是对赌（缺保险利益原则）→ 只能自称"可审计的参数化赔付通道" |

**结论**：如果资金与时间允许，v2 值得做；它的收益不在分数上，而在**把"我们有洞但我们知道"变成"我们已经补了"** —— 后者是评委最喜欢听到的话。
