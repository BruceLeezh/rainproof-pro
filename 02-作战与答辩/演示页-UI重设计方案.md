# 演示页 UI 重设计方案 · 雨证 RainProof

> 目标文件：`05-演示站点/index.html`（991 行：CSS 7–166、DOM 168–301、内联 ABI 与 JS 304–991）
> 前提约束：**背景雨幕（`#rainLayer` canvas + 深色底）保留不动**；所有被 JS 引用的 23 个 id 与 5 个 class 钩子必须存活（`07-测试工具/check-ui.js` 第 ③ 段就是查这个）。
> 本文只讨论界面。不涉及合约、AI 判定层与证据链。

## 〇、三句结论

1. **"AI 痕迹"的不是配色，是"同构"**：七个区块全部是同一个模子（左侧 4px 色条标题 + 半透明卡 + 1px 蓝边 + 14px 圆角 + 内高光），所以整页像一张张卡堆出来的，而不是一个工具。
2. **第二重痕迹是"把说明文档塞进界面"**：`#buyHint`、池子 note、看板副标题、footer 五段，全是"解释给人听"的长句 —— 成熟产品把解释放进 tooltip / 折叠区 / 独立说明页，主视线只留**操作与结果**。
3. **修法不是换皮，是重排信息架构**：把"链上事实 / AI 判定 / 我的钱"三层在一屏内分开呈现；颜色只表状态，层级靠字重、留白与对齐。

## 一、诊断：现在这页为什么"AI 痕迹重"（逐条带行号）

| # | 现象 | 位置 | 为什么显得"生成式" |
|---|---|---|---|
| 1 | 七个区块同构：`section.sec > h2` + `.panel` | `:49-56`；DOM `:188/207/241/248/272/279` | 真实产品里"主区/侧区/表区/设置区"长相不同；同构=模板感 |

| 9 | 长说明占有主视线 | `#buyHint :235-237`、池子 note `:262-265`、看板 h2 em `:273`、footer `:288-298` | "把文档写进界面"是文档型输出，不是产品界面 |
| 10 | 控件原生外观 + 长文案 | `select :217-221`（含"（3 天，最长）"）、`#fundBtn :261`（"（自动按钱包余额封顶）"） | 控件文案应短，约束用副文本或 tooltip |

| 12 | 空态与禁用态弱：`.empty` 用斜体、`.btn:disabled` 仅 `opacity .42` | `:140`、`:72` | 中文伪斜体难看；禁用态对比度不足 |

## 二、要保留的东西（背景是资产，不是装饰）

- `#rainLayer` canvas（`:169-170`、JS `:879`）：**雨量越大雨越密**，它是"参数化"这件事唯一的**通感表达** —— 用户说得好，"背景设计很好"，因为它不是纹理，是数据。
- `:23-27` 的三层径向渐变底色：与雨幕同调，保留，但**只保留在 header 区**（`body` 上的 `radial-gradient` 下移到 header），让内容区回到干净平面。
- "标了「背景雨幕」的那一行就是背景雨的来源"（`:110-115`）：**这是本页最好的一个设计**（把背景与选中行做因果绑定）。保留，并升级为"刻度尺 + 阈值线 + 实时值"三件套。

## 三、三个可选方案

### 方案 A（推荐）工作台 Workbench

```
┌ 顶栏 ─ 品牌 · 网络/区块/合约（细边、无卡片、可复制）────────────── [配置] ┐
├ 结论条 KPI（通栏 4 格）───────────────────────────────────────────────┤
│ 池子余额 0.0512 │ 已越阈值 2/5 区 │ 待判定 1 笔 │ 已赔付 1 笔(0.01)        │
├──────────────────────────────┬────────────────────────────────────────┤
│ 降雨看板（主区 2/3）           │ 投保（右栏 1/3，sticky）                 │
│  区域 · 值 · 刻度尺 · 阈值线    │  区域 / 时长 / 保费 / 触发线 / [投保]     │
│  选中行 = 背景雨幕来源          │  一行小字：赔付按投保后增量算             │
├──────────────────────────────┴────────────────────────────────────────┤
│ 我的保单（通栏表格：保单 区域 状态 期间 增量/阈值 AI判定 哈希 操作）        │
├───────────────────────────────────────────────────────────────────────┤
│ 链上动态（通栏表格：时间 事件 对象 关键值 交易）                           │
├───────────────────────────────────────────────────────────────────────┤
│ ▸ 合约配置　▸ 诚实说明（默认折叠）                                        │
└───────────────────────────────────────────────────────────────────────┘
        canvas 雨幕（不动）
```

- **信息架构**：KPI（一句话结论）→ 主操作（投保）→ 主事实（看板）→ 明细（保单、事件）→ 设置与声明（折叠）。
- **改动量**：CSS 重写 style 块约 60%；HTML 重排约 120 行；JS 只改两处模板字符串（保单列表、事件流）。
- **代价**：8 张截图 + 60 秒录屏必须重做。
- **适合**：既有 6 分钟演示动线（问题→投保→看板→判定→赔付→核验）**完全同构**，讲的时候手指到哪看到哪。

### 方案 B 终端 Console

12 列网格 + 左窄状态栏 + 中间"区域矩阵"（五城 × 24/48/72 网格着色）+ 右侧操作栈；视觉靠近 Etherscan / DefiLlama / 交易终端。

- **优点**：专业感最强，一眼"链上工具"。
- **代价**：HTML 结构大改、中文在小格子里难排、6 分钟内观众容易迷路；改动量 ≈ 2 倍方案 A。
- **适合**：给评委看的"数据墙"截图，而不是现场讲故事的界面。

### 方案 C 单列叙事 Narrative

按演示动线串成纵向时间线：问题 → 参数化 → 投保 → 看板 → 判定 → 赔付 → 核验，每屏一个焦点，滚动即推进。

- **优点**：录屏与答辩最省力（跟着滚就行）。
- **代价**：不像"产品"，像 PPT；评审"技术完成度"会吃亏（一个真正的工具不该是一条流水账）。
- **适合**：录 3–5 分钟视频时用，演示页本身不采用。

| 维度 | A 工作台 | B 终端 | C 叙事 |
|---|---|---|---|
| 一屏看懂三层 | ★★★ | ★★ | ★ |
| 专业感 | ★★ | ★★★ | ★ |
| 改动量 | 中 | 大 | 小 |
| 破坏既有动线 | 否 | 部分 | 是（改讲法） |
| 与 check-ui 兼容 | 完全 | 需改 JS 钩子 | 完全 |

## 五、方案 A 的具体修改清单

### 5.1 设计 token（把 8 种圆角、10 档字号、4 处渐变收干净）

| 变量 | 现值 | 改为 | 理由 |
|---|---|---|---|
| `--blue` | 主色 + 边框 + 链接 + 数值 | 保留为主色，**只用于主操作、链接、选中态** | 边框改用中性色 `rgba(150,180,220,.14)` |
| `--amber` | warn + 品牌强调 + 金额 | 拆成 `--warn`（状态）与 `--accent`（只给金额/赔付） | 颜色=状态，不再兼任装饰 |
| `--card` / `.panel` | `rgba(9,19,34,.62)` + blue 边 + inset 高光 + blur | `rgba(10,20,36,.72)`、**1px 中性边**、去 blur、去高光 | 文字对比度稳定，卡片不再发光 |
| 圆角 | 14/12/11/10/8/6/5/99 | **10 容器 / 8 控件 / 6 标签 / 99 进度** | 四档够用 |
| 渐变 | logo、按钮、进度条、body 四处 | 只留 body（背景）与进度条填充；按钮改**实底 + 边** | 去"发光按钮" |
| 阴影 | logo 外发光、`bar::after` 发光、toast 阴影 | 只留 toast 与 sticky 容器 | 层级靠边与留白 |
| 字阶 | 10 档 | **32 KPI / 20 H1 / 15 区标题 / 13 正文 / 12 表 / 11 标签**（6 档） | 层级可数 |
| 数值 | 混排 | 全部 `var(--mono)` + `font-variant-numeric:tabular-nums` + **右对齐** | 切换区域时数字不跳动 |
| 说明段宽 | 满宽 1180px | `max-width:64ch` | 长句可读，且视觉上"退居次要" |

### 5.2 模块划分（新信息架构 ↔ 现有 id 的对应）

| 新模块 | 内容 | 数据来源（现有 id，**不改名**） |
|---|---|---|
| 顶栏 | 品牌、网络/区块/合约、配置入口 | `netText` `dot` `blk` `addrMini` `addrInput` `saveBtn` `walletBtn` `modeTag` `cfgHint` |
| 结论条 KPI（新） | 池子余额 / 已越阈值区域数 / 待判定笔数 / 已赔付笔数与金额 | 复用 `poolBal` `poolCap` `rainBoard` `myPolicies` 的读值，**新增一个 render 函数**，不新增 id 也可（用 class） |
| 投保（右栏 sticky） | 区域、时长、保费、触发线、投保按钮 | `regionSel` `hoursInput` `premiumShow` `threshShow` `buyBtn` `buyHint` `payoutShow` |
| 降雨看板（左主区） | 五区刻度尺 + 阈值线 + 实时值 + 选中态 | `rainBoard` `.region` `.is-sel` `dataset.region` |
| 我的保单（通栏表） | 保单/区域/状态/期间/增量(阈值)/AI 判定/哈希/操作 | `myPolicies` `[data-claim]` |
| 链上动态（通栏表） | 时间/事件/对象/关键值/交易 | `events` |
| 资金池 | 并入 KPI 与投保区；`fundBtn` 保留在折叠的"运营"区 | `poolBal` `poolCap` `fundBtn` |
| 折叠区 | 合约配置、诚实说明、数据源 | `cfgHint`、footer 文案 |

### 5.3 逐条改动点

**结构（HTML，`:168-301`）**

| 位置 | 现在 | 改为 | 理由 | 预期效果 |
|---|---|---|---|---|
| `:175` | `.logo` = `🌧` emoji | 几何字标（圆角方块内 `雨` 或 `RP`） | 去生成式标记 | 首屏不再有 emoji |
| `:185` 后 | 无 | 新增结论条（KPI 4 格，通栏） | 6 秒内给结论 | 观众先看到"池子够不够、几个区已经触发" |
| `:204` | `grid2` = `1.05fr .95fr` | `1.6fr .9fr`，且保单/事件移出 grid | 主区（看板）加宽，明细通栏 | 看板刻度尺可读，表格不被挤 |
| `:207-239` | 投保在左栏第一位 | 移到右栏顶部 + `position:sticky;top:16px` | 操作与事实同屏 | 滚动看明细时投保一直在 |
| `:241-246` | 保单=卡片列表 `.pol` | 通栏**表格**（8 列） | 多条保单可比 | 一眼比较各保单状态与增量 |
| `:248-267` | 资金池独立区块 + 4 行长 note | 余额进 KPI；`fundBtn` 进折叠"运营"区 | 它是运营动作，不是用户动线 | 主视线少一个区块 |
| `:279-284` | 事件=`.ev` 标签流 | 通栏**表格**（时间/事件/对象/关键值/交易） | 链上工具的标准形态 | AI 判定那几行可横向对齐比较 |
| `:188-202` | 配置=大区块 | 顶栏右侧按钮 → 折叠面板 | 一次性设置 | 首屏省下 120px |
| `:288-298` | footer 五段 | 3 行 + `<details>` 装诚实说明 | 声明该有，但不该占道 | 首屏无长文 |

**样式（CSS）**：`--` token 表（5.1）逐项落地；删 `:100-108` 的流光动画与 `@keyframes barflow`；`.bar` 从"胶囊进度条"改为**刻度尺**（底轴 + 刻度 + 阈值竖线 + 填充）；`:140` `.empty` 去斜体；`:72` 禁用态改 `opacity:.55 + 虚线边`。

**文案**

| 现在 | 改为 | 去哪 |
|---|---|---|
| h2 em「1 份 0.001 SepETH」 | 徽标 `0.001 SepETH/份` | 同位置 |
| 看板 h2 em：「链上的累计值，由喂价脚本写入；标了「背景雨幕」的那一行…」 | 删除；改右下角 11px 单行「链上累计值 · 选中行驱动背景雨幕」 | h2 只留标题 |
| `#buyHint` 两句 | 单行 11px「赔付按**投保后的增量**算（基线=投保当刻链上雨量）」；完整口径进 `<details>` | 折叠区 |
| 池子 note 4 行 | 删；（"池子空了第一笔赔付就过不去"这句留到讲稿） | 讲稿 |
| `#fundBtn`「注资到资金池（自动按钱包余额封顶）」 | 「注资」+ `title` | 控件 |
| `#buyBtn`「连接钱包后投保」 | 未连钱包时就是「连接钱包」，连上后「投保」 | 控件 |
| footer 五段 | 3 行 + `<details>诚实说明</details>` | 折叠区 |

**动效**：常驻装饰动画 3 → 1（只留背景雨幕）；阈值越线用 300ms 变色（金）；数值更新用 200ms 淡入；`toast` 与 `.loading` 保留。

### 5.4 契约边界（不能踩的线）

JS 引用的 **23 个 id**：`toast` `modeTag` `addrInput` `blk` `dot` `netText` `walletBtn` `addrMini` `premiumShow` `payoutShow` `threshShow` `hoursInput` `cfgHint` `buyBtn` `fundBtn` `rainBoard` `regionSel` `poolBal` `poolCap` `myPolicies` `events` `saveBtn` `rainLayer`（另有 JS 动态创建的 `#fakeChainBar`）。
**5 个 class 钩子**：`.tag`、`.dot(.on/.err)`、`.mono`、`#rainBoard .region` + `dataset.region` + `.is-sel`、`#myPolicies [data-claim]`。
→ 只要这些存活，`check-ui.js` 第 ③ 段（DOM 契约）就绿；第 ① ② ⑤ 段（刻度公式、三档下拉、判定口径文案）也必须继续满足。

## 七、排期（两档，任选）

- **档 1 · 今晚 40 分钟（零结构风险）**：只做 5.1 token + 动效 + 文案 + 顶栏/折叠。**不动一个 id、不动 JS 逻辑**。做完 → 重拍截图 → 录 60 秒。视觉上"去 AI 痕迹"的 60% 来自这一步（去发光、去渐变、去流光、去 emoji、说明文字退场）。

## 九、as-built：2026-10-07 实际落地的版本

方案选了「最完善的那一档」（结构层全量重排）。**页面行为与 JS 契约零改动**：
`07-测试工具/check-ui.js` 的 21 项（含 ③ DOM 契约里 JS 引用的那 23 个 id）与四道后端门禁一起复跑 = **232/0**。

| 改动 | 落地形态 | 理由（craft floor） |
|---|---|---|
| 顶栏 | emoji `🌧` → 手绘 SVG 几何标记；链栏只留「网络 + 区块 + 连接钱包」 | 禁 emoji 当图标；标题上方不许 kicker |
| 状态 rail | 原「资金池」卡片拆成顶栏下的一条 3 格 rail（余额 / 剩余可赔付 / 合约） | 禁 hero-metric 卡组；数据贴住它描述的对象 |
| 模块重排 | 左栏 = 降雨看板 + 链上动态；右栏 = 投保（`position:sticky`）；我的保单整行；配置与运营折进 `<details>` | Operate 页：扫描性优先，说明退到折叠区 |
| 保单 / 事件 | 卡片堆 → 两个真数据行网格（`.pol` 4 列带表头、`.ev` 4 列） | 卡片是惰性容器；数字用 `tabular-nums` |
| 层级 | 去掉全部「描边 + 内高光」双声明；卡片圆角 12px、胶囊只给 tag | elevation 只声明一次 |
| 颜色 | 蓝=可操作 / 金=金额与赔付 / 绿红=状态；去掉渐变按钮 | 颜色只表状态 |
| 动效 | 删掉看板流光 `barflow` 与全部常驻动画，只留宽度过渡 + toast 的指数缓出 | 一个作者化的时刻 |
| 浏览器表面 | `::selection`、caret、滚动条、`:focus-visible` 焦点环、`::placeholder`、`overflow-wrap` | 「被搭建过」最便宜的信号 |
| 口径 | 触发线仍是 1px 琥珀线且严格落在 50%（与 `pct = v/(阈值×2)` 对齐）—— **广州 50mm 的填充正好终止在线上** | ① 的视觉证据 |
