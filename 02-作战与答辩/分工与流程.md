## 1. 分工原则（三条，别违反）

1. **按文件切，不按"模块"切。** 同一个文件同一时刻只能有一个人改。两人同时改一个文件 = 必然冲突 + 必然浪费时间。
2. **接口只冻一次。** 下面第 2 节列的东西改一个，两个人都要同时知道，且要重跑校验。
3. **每一步都要留下别人能独立复核的产物**（日志、截图、哈希、数字）。口头说"我弄好了"不算完成。

## 5. 两机协同规则（照着做，能省下几小时）

1. **动手前先 `git pull --rebase`**，推送前再 pull 一次。
2. **一个文件同一时刻只有一个 owner**（见第 3 节）。要改别人的文件，先在群里说一句。
3. **小步提交，提交信息带前缀**：`[A] ...` / `[B] ...`。这样出问题一眼能看出是谁的改动。
4. **不要两个人同时跑本地链。** 8545 端口只有一条。而且 Windows 允许两个进程同时绑同一个端口（未设 `SO_EXCLUSIVEADDRUSE`），症状是莫名其妙的 `transaction execution reverted` —— **遇到没有上下文的 revert，先查端口和残留进程，不要往合约逻辑里找。**
5. **`.env` 和 `07-测试工具/_local_chain.json` 各自本地保留，绝不互相传私钥，绝不提交**（`.gitignore` 已实测挡住）。
6. **不要 `git push -f`。** 冲突了就让仓库 owner 处理。
7. 文档里贴截图请放 `08-截图存证/`，别把图丢在临时目录。
