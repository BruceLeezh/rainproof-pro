## 2. 公式（派生指标全从这四个式子出来，没有第五个）

```
杠杆      L = PAYOUT / PREMIUM
赔付率    R = E[赔付] / PREMIUM = p × L          （二元全额赔付时 E[赔付] = p × PAYOUT）
公平保费  P_fair = E[赔付]                        （此时 R = 100%，L = 1/p）
定价反解  PREMIUM(R*) = E[赔付] / R*
保本      R < 1  ⟺  PREMIUM > E[赔付]  ⟺  L < 1/p
```

**关键点：`L` 和 `R` 只有一个能自由选。** 先钉住目标赔付率 `R*`，杠杆就被 `p` 反解出来了 —— 所以杠杆是**结果**，不是**设定**。我们钉 `R* = 60%`。

**同理，"赔付率是多少"这个问题在不给出保费时没有答案。** 以武汉 72h 为例（`E[赔付] = p × PAYOUT = 4.7696e-4 ETH` 固定）：

| 保费 PREMIUM | 0.0004 | 0.0006 | **0.0008（现价）** | **0.000795（= P_fair/0.6）** | 0.0010（默认值） | 0.0020 |
|---|---|---|---|---|---|---|
| 杠杆 L | 25.0 | 16.7 | **12.5** | 12.6 | 10.0 | 5.0 |
| 赔付率 R | 119.2% | 79.5% | **59.6%** | 60.0% | 47.7% | 23.9% |
| 判定 | ❌ 亏 | ✅ | ✅ | ✅（目标） | ✅ | ✅ |

## 2.1 `R* = 60%` 是怎么来的（它是决策变量，但**可选范围是算出来的**）

**先说清它不是什么**：`R*` 不能从历史数据里"推"出来 —— 它是承保人设定的**目标**。数据只能给 `p`；给定 `p`，`R*` 与 `L` 只有一个是自由的（§2）。任何声称"60% 是从数据算出来的"的说法都不老实。**它是选的，但选在哪个范围里、为什么这个范围是有限的，可以算。**

### 一、经济含义

`R* = 60%` ⟺ 每 100 元保费里 60 元用于赔付，剩下 40 元要同时覆盖三件事：**每笔交易的链上固定成本、准备金积累、operator 利润**。所以 `R*` 的上限由成本决定：成本越重，`R*` 只能定得越低（= 保费收得越贵）。

### 二、外部锚（为什么锚在 60% 而不是 80%）

政策性农险的操作带。财政部《农业保险大灾风险准备金管理办法》（2014-01-01 施行）**第十条**「综合赔付率**低于 70%**」才认定承保盈利（要计提利润准备金、分红受限）；**第十四条**「**超过 75%**」才可动用大灾准备金 —— **是两个不同门槛，不是"70–75%"一个区间**。→ 农险的实际操作带落在 **70–75%**，**我们取 60%，定在这个带的下方，主动更保守**。（出处与核实过程见 [`P1-18-待核四项-核实记录.md`](../02-作战与答辩/P1-18-待核四项-核实记录.md) §一。）

### 三、可行上界（**这一步是算的**）

把每笔固定成本 `C` 显式减掉：要求的保费 `P = E[赔付]/R*` 必须覆盖赔付与成本

```
E[赔付] / R*  ≥  E[赔付] + C     ⟹     R*  ≤  E[赔付] / (E[赔付] + C)
```

`C` 有两种口径，**必须分开写，否则"北京到底亏不亏"会给出相反答案**：

| 口径 | `C` | 含义 |
|---|---|---|
| 保守 | `judge + payout` = **0.00025** | 把赔付那笔 gas 也摊到**每一份**保单上（上界） |
| 期望 | `judge + p × payout` ≈ **0.000135** | 判定每份都要付，**赔付只在出险时付** —— 池子的真实长期支出 |

72h 口径下：

| 城市 | E[赔付] | **R\* 上界（保守）** | **R\* 上界（期望）** | 我们取 60% | 现价净毛利（保守 / 期望） |
|---|---|---|---|---|---|
| 武汉 | 4.770e-4 | 65.6% | 77.8% | 60% | +7.30e-5 / +1.87e-4 |
| 上海 | 4.557e-4 | 64.6% | 77.1% | 60% | +9.43e-5 / +2.09e-4 |
| 北京 | 2.281e-4 | **47.7%** | **63.2%** | 60% | **−7.81e-5 / +3.92e-5** |
| 广州 | 1.157e-3 | 82.2% | 88.9% | 60% | +5.93e-4 / +6.99e-4 |
| 成都 | 3.723e-4 | **59.8%** | 73.5% | 60% | +7.77e-5 / +1.93e-4 |

复算：`cd 10-金融与定价 && node derive_metrics.js --self-check`（上表逐城在两种口径下断言"上界处公式价恰 = E + C，毛利为零"，共 **50 项**恒等式）。

### 四、这张表给出的三个结论

1. **`R* = 60%` 落在期望口径的可行区间内（五城上界 63.2%–88.9%），但落到保守口径就不够用**：北京上界只有 47.7%、成都 59.8%。**所以"北京档卖一份亏一份"这句话的成立与否，取决于成本口径，必须说清是哪一种。**
   - 保守口径（把赔付 gas 摊到每一份）：北京净 **−7.81e-5**，成都靠上整到 0.0007 才转正。
   - 期望口径（赔付 gas 只在出险时付）：北京净 **+3.92e-5**，五城全为正。
2. **真正压住 `R*` 的不是风险，是 `C` 相对 `E` 的大小。** 北京 72h 的 `E` 只有 2.281e-4，而单份判定 gas 就是 1.3e-4 —— **成本与风险同量级**。降低 `C`（批量判定 / L2）比调 `R*` 更有效。
3. **R\* 不是孤立常数，它随区域与窗口变**：同一个 60% 在 24h 档的可行上界要低得多（`E` 更小、`C` 不变），这就是 §5 说"短窗口在 L1 上不成立"、v2 只放 24/48/72 三档并设 `MIN_PREMIUM = 0.0002` 地板的定量理由。

## 3. v1 结果（现行链上口径：阈值恒 50mm、达标全额赔 0.01 ETH）

`每份净毛利 = PREMIUM − E[赔付] − 每份运营成本`（成本 = 判定 ≈0.00013 + 赔付 ≈0.00012）

> ⚠️ **成本口径**：表里用的是**保守口径 0.00025**（把赔付那笔 gas 也摊到每一份保单上）。池子的真实长期支出是**期望口径 `0.00013 + p × 0.00012 ≈ 0.000135`**（赔付只在出险时付）。**两者会翻转"北京是否亏损"的符号**，见 §2.1 与 §5。

### 3.2 三个必须说清的点

1. **"10 倍杠杆"是默认值 `PREMIUM = 0.001` 的副产品。** 用它算保本线 = `1/10 = 10%` 触发概率，而广州点估计 11.57% 越线 —— 这就是"广州一定亏"那套说法的来源。**但没人用这个价**：`premiumOf()` 读的是 `aiPremium`，链上现价让五城各自的 R 都在保本线内。
2. **北京现价在保守口径下卖一份亏一份，在期望口径下转为微利**：保守 `0.0004 < 2.281e-4 + 2.5e-4 = 4.781e-4` → 净 **−7.81e-5**；期望 `0.0004 > 2.281e-4 + 1.327e-4 = 3.608e-4` → 净 **+3.92e-5**。**两种口径都不是"风险定价错了"，而是 `C` 相对 `E` 太大**（北京 72h 的期望赔付 2.281e-4 与单份判定 gas 1.3e-4 同量级）—— 所以对外必须写明是哪一种口径，见 §2.1 三 / §5。
   另有一条**不依赖口径**的硬事实：**骑手端投保手续费 ≈0.00046 ETH > 北京档保费 0.0004 ETH** —— 在北京以这个价卖，骑手付的手续费比保费本身还贵。这条与池子盈亏无关，是产品可用性问题。
3. **168h 列不可售**（v1 `MAX_HOURS = 72`），列出来只为说明"自然 7 天窗口"的风险量级；它的 R 都超过 100%，提醒我们**不要卖 7 天档**。

  `reserve ≥ Σ_区域(该区域在保保单数 × PAYOUT)` **= 未了结保单数 × PAYOUT**（取**总和**，不是各区域取最大）

- **VaR99 的信息量上限**：真实日历月只有 132 个 → 99% 分位约 1.32 个独立月的信息量 → **对外主推 VaR95 / P(当月亏损) / E[损益]**

## 7. 计算依据与复现

| 指标 | 计算依据 | 复现命令 |
|---|---|---|
| p（全部窗口） | ERA5 逐小时 + 整数十分位滑动窗口 | `node audit_numbers.js --self-check`（17 项断言） |
| L / R / P_fair / 保本线 | §2 的四个公式，p 与现价代入 | `node derive_metrics.js --self-check`（50 项恒等式） |
| R* 的可行上界（两种成本口径） | §2.1 三：`R* ≤ E/(E+C)` | `node derive_metrics.js --self-check`（10 条上界处零毛利断言 + 口径翻转断言） |
| E[赔付]（v2 分档） | `tierOf`/`tierBps` 逐档求和 | 同上（与 `RainDeliveryInsuranceV2.sol:172-192` 逐字对齐） |
| 准备金分位 | 30 天块自助法 3000 次，固定种子 42 | `node reserve_mc.js --seed 42` |
| 链上保费/余额等 | `premiumOf` / `poolBalance` / `reserve` 只读调用 | `node derive_metrics.js --chain` |

**自检不是形式**：`derive_metrics.js --self-check` 会逐城验证 `R = p × L`、`公平保费处 R = 1`、`L_保本 = 1/p`、`L_现价 = PAYOUT/PREMIUM`、`按 R*=60% 定价回代 = 0.6`。任何一条失败都说明公式或输入被改坏，此时本文所有数字不可信。

**已知的计算局限（不是算错，是信息量上限）**：
- 相关性：10 对城市里只有武汉-上海（φ=0.2469）与北京-成都（φ=0.0874）显著，其余 8 对 0.70–1.38×；`reserve_mc.js:224` 在区域循环内取 `base`，**隐含假设五城独立** → 该 VaR 是**下界**（改成同块驱动后实测 +49.6%）
- 空间基差：ERA5 格点 ≠ 地面站网（2017-05-07 广州格点 72h 仅 31.70mm，同日官方全市 239 站 ≥50mm）→ 真实 p 可能更高
- 抽样不确定性：广州 72h 的 95% 区间 [9.35%, 13.88%] 跨越 10% → **"广州越线"不显著，对外讲区间不讲点值**
