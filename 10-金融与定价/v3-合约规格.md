## 0. 一句话

v2 的保费只有 `(regionId, hours)` 两个维度；v3 需要 **`(regionId, hours, riderTier, channel, count)`** 五个。要落地，`premiumGrid` 必须从**一维表**变成**两维表（零售 + 批量带）**，`premiumOf()` 签名必须变，`MIN_PREMIUM` 必须降一个数量级，**`hours` 的合法集合必须从 `{24,48,72}` 收成 `{12,24}`**。

**没有这一改，v3 的 40 格零售价会退化成 v2 的 15 格，120 格批量价全部被拒。**

## 1. 必须改的四件硬事

### 1.1 `MIN_PREMIUM` 从 `0.0002 ether` 降到 `0.00002 ether`

v2：`03-合约/RainDeliveryInsuranceV2.sol` `uint256 public constant MIN_PREMIUM = 0.0002 ether;`，且 `setPremiumGrid` 有 `require(premium >= MIN_PREMIUM && premium < PAYOUT_MAX)`。

v3 的批量价最低到 **0.00006 ETH**（北京 12h 平台团体 N=1000）。**不改就是批量档全部 `revert`。**

稳妥做法：拆成两个常量，别动零售语义 ——

```solidity
uint256 public constant MIN_PREMIUM_RETAIL = 0.00002 ether;  // 原来是 0.0002，零售地板
uint256 public constant MIN_PREMIUM_BAND   = 0.00002 ether;  // 批量地板
```

> ⚠️ 如果只是为了赛事演示想少改，最小改动是**直接把 `MIN_PREMIUM` 改成 `0.00002 ether`**。但它同时是 `premiumOf()` 的最终地板，会同时放开 `aiPremium` / `PREMIUM_DEFAULT` 两条旧路径 —— 建议还是拆常量。

### 1.3 `hours` 的合法集合从 `{24, 48, 72}` 收成 `{12, 24}`

**这条是本轮新增的，和 §1.1/§1.2 并列，不是"顺带改"。**

v2 的 `hoursAllowed` / `MIN_HOURS=1` / `MAX_HOURS=72` / `thresholdOf(hours) = THRESHOLD_PER_24H * hours / 24` 构成一套**任意时长 + 线性外推档线**的口径。v3 回到国标：**只有 12h 与 24h 两个时长**，档线是国标表 1 的暴雨 / 大暴雨下限查表，**不再有 `thresholdOf` 这个函数**。

```solidity
// v2
function thresholdOf(uint256 hours_) public pure returns (uint256) {
    return THRESHOLD_PER_24H * hours_ / 24;      // 50 / 100 / 150 @ 24/48/72h
}

// v3 —— 查表，不再外推
uint256 public constant HOURS_12 = 12;
uint256 public constant HOURS_24 = 24;
function tierThreshold(uint256 hours_, uint8 tier) public pure returns (uint256) {
    // GB/T 28592-2012 表 1：12h 暴雨 30.0~69.9 / 大暴雨 70.0~139.9
    //                        24h 暴雨 50.0~99.9 / 大暴雨 100.0~249.9
    if (hours_ == 12) return tier == 0 ? 30 : 70;
    if (hours_ == 24) return tier == 0 ? 50 : 100;
    revert("unsupported window");
}
```

配套要一起动的：`buyPolicy` / `buyPolicyBatch` 必须 `require(hours_ == 12 || hours_ == 24)`；`hoursAllowed` 的默认集合；`04-脚本/` 里按 24/48/72 循环的喂价与建单脚本；`05-演示站点/` 的时长选择器（从三个选项变两个）。

**为什么必须删 48h/72h**（详见 `定价体系-v3.md` §0）：国标 §3 原文「降雨量按 **12 h，24 h 两个时间段**进行划分」；v2 的线性外推被国标自己的两列证伪（24h÷12h = **1.667 / 1.429 / 1.786，没有一个是 2**）；实测更直接，**同基数**（武汉，拿链上 v2 自己的 24h 与 72h 比）：保费 0.0002 → 0.0008（**多付 4 倍**），档 0 触发率 0.4377% → 0.2117%（**中奖率降到 1/2.07**）—— **买家多付钱、换到更低的中奖概率**。（常被引用的"72h 只有 12h 的 1/4"是**跨档线**比的：v2 72h 的 150mm 对 v3 12h 的 30mm，基数不同，引用时须带档线。）

### 1.4 赔付档从三档变两档（`TIER_BPS`）

```solidity
// v2
uint256[3] public TIER_BPS = [5000, 7500, 10000];   // 50% / 75% / 100%，第 3 档 = 特大暴雨

// v3
uint256[2] public TIER_BPS = [5000, 7500];          // 50% / 75%，只卖国标的前两档
```

**为什么砍掉第三档（特大暴雨）**：国标 24h 特大暴雨线 ≥250mm 在五城 11 年逐小时窗口里 **零命中**；12h 的 ≥140mm 也只有 0.002%~0.007%（武汉 4 次 / 上海 0 / 北京 2 / 广州 2 / 成都 7）。**v2 的第 3 档（`250 × h/24` mm，72h 即 750mm）在 11 年里一次都没触发过 —— 我们刚把它定性成"虚假承诺"，不能换个出处再犯一次。**

> `Policy.tier` 字段保留，取值域从 `{0,1,2}` 收成 `{0,1}`。`settleExpired` / `submitJudgement` 里任何 `tier == 2` 的分支都要删干净，不能留下不可达的死代码。

## 2. 数据结构 diff

```solidity
// ── v2 现有 ──
mapping(uint8 => mapping(uint256 => uint256)) public premiumGrid;   // [region][hours] → 价
mapping(uint8 => uint256) public aiPremium;                          // [region] → 价
uint256 public constant MIN_PREMIUM = 0.0002 ether;                  // ❌ 要降
uint256 public constant PAYOUT_MAX  = 0.01 ether;

// ── v3 新增/替换 ──
uint256 public constant SEGMENT_COUNT = 4;      // 合法 (riderTier, channel) 组合数
uint256 public constant BAND_COUNT    = 6;      // BATCH_N = [1,10,50,100,500,1000]
uint256 public constant MAX_BATCH_MINT = 100;   // 单笔 buyPolicyBatch 的上限（gas 约束）

/// 零售价：[regionId][hours][segId] → wei。0 表示"这一格不卖"。
mapping(uint8 => mapping(uint256 => uint256[SEGMENT_COUNT])) public premiumRetail;

/// 批量单价：[regionId][hours][segId][band] → wei。band 0 恒等于零售价。
mapping(uint8 => mapping(uint256 => uint256[SEGMENT_COUNT][BAND_COUNT])) public premiumBand;

/// 平台在 (region,hours,seg) 上的月度承诺量 → 决定用哪个 band
mapping(address => mapping(bytes32 => uint256)) public platformCommitment;
mapping(address => uint8) public riderTierOf;                       // 0=open 1=attested 2=group
```

> **`0` 是"不卖"的哨兵值**，不是"免费"。`premiumOf()` 见到 0 必须 `revert("not offered")`，**不能回退到别的价** —— 回退意味着我们在卖一个自己认定不该卖的东西。这是 B 的定价结论（`定价体系-v3.md` §5），不是实现细节。
>
> **本批 40 格全部可售，0 格触发这个哨兵。** 保留这条路径是因为删掉它 = 把"我们不卖"这个能力从合约里拿掉；留着它，将来任何一格报不出价时我们仍然能诚实地拒绝，而不是悄悄按别的价卖。**原先触发它的 3 格（武汉/广州/成都 72h 众包自助，诚实价 0.00205 / 0.00211 / 0.00287 > 上限）随 72h 一起消失。**

### 2.1 索引顺序（这里踩过一个真 bug，别重犯）

Solidity 定长多维数组的下标**从右往左**对应声明顺序。`uint256[SEGMENT_COUNT][BAND_COUNT] premiumBand` 的写法读作 `premiumBand[region][hours][seg][band]`，而底层类型是 `uint256[4][6]` —— **内层 4 = seg、外层 6 = band**。

写反会得到 `Panic(0x32) ARRAY_RANGE_ERROR`（下标越界），不是编译错误。B 的参考实现 `ref/PricingV3.sol` 第一次就是这么挂的，靠 solc 真编译跑出来才抓到。**这正好是评委爱问的"你到底跑没跑过"的答案 —— 我们跑了，而且它真的报错了。**

### 2.2 segId 必须与引擎逐字一致

```solidity
/// AGENTS.md §6：这是冻结接口，改了必须两边同时改。
/// 与 10-金融与定价/pricing_engine.js 的 SEGMENTS 顺序逐字对应：
///   0 = (2,1) 平台团体 · 平台代付      κ=0.00
///   1 = (1,1) 认证骑手 · 平台代付      κ=0.15
///   2 = (1,0) 认证骑手 · 自助投保      κ=0.55
///   3 = (0,0) 众包自助 · 自助投保      κ=1.00
function segmentId(uint8 riderTier, uint8 channel) public pure returns (uint8) {
    if (riderTier == 2 && channel == 1) return 0;
    if (riderTier == 1 && channel == 1) return 1;
    if (riderTier == 1 && channel == 0) return 2;
    if (riderTier == 0 && channel == 0) return 3;
    revert("illegal segment");   // (2,0) (0,1) (2,2) 以及已下线的 channel=2
}
```

**注意**：`channel=2`（预警增保）**在 v3 里彻底下线**（理由见 `定价体系-v3.md` §7：冷静期已锁死 + 自述不可核验 + 定量上次要）。`segmentId` 必须对它 `revert`，不能留"以后再说"的后门。

### 2.3 band 选择

```solidity
/// 与 pricing-engine.json 的 BATCH_N = [1,10,50,100,500,1000] 对应
function bandOf(uint256 count) public pure returns (uint8) {
    if (count >= 1000) return 5;
    if (count >=  500) return 4;
    if (count >=  100) return 3;
    if (count >=   50) return 2;
    if (count >=   10) return 1;
    return 0;
}
```

**设计选择（需要 A 确认）**：`count` 取的是**平台对该 `(region,hours,seg)` 的月度承诺量**，不是单笔交易份数。原因有三：

1. **gas**：一份保单约 170k gas（`buyPolicy` 实测 170,979），单笔 1000 份要 170M gas，远超区块上限。所以单笔有 `MAX_BATCH_MINT = 100`。
2. 若按单笔份数定价，`N=500/1000` 两档**在链上永远不可达**，等于写了两条死条款。
3. 月度承诺量是 B2B 保险的标准做法，平台侧可核验、可实现。

承诺量由平台自己声明（`setPlatformCommitment`），当前**不做事后差额结算**。
`// ponytail: 未做"承诺未达标补差价"，演示够用；产品化时加 settleCommitment() 在月末按实际量补差。`
