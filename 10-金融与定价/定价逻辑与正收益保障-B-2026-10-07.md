## 一、定价逻辑

### 1.1 定价公式

每份保费（网格粒度 `TICK = 0.00001 ETH`，一律**向上取整**）：

```
P(N)  = max( P_net(N),  F(N),  MIN_PREMIUM )          … 实际收取
P_net(N) = ceilTick( ( E_upper + C(N,q) ) / R* )      … 风险腿：按 97.5% 统计上界定
F(N)     = ceilTick( C(N,q) × (1 + M) )               … 成本腿：固定成本加成
C(N,q)   = JUDGE_GAS / N  +  q × PAYOUT_GAS           … 每份固定成本
```

其中 `q = E[f]` 是本格的**档位加权期望赔付比例**（无量纲，`q ≤ 1`），`E_upper` 是它的 97.5% 上界，`R*` 是目标赔付率。
**两份约束谁大谁生效**，产物里记在 `boundBy` 字段（`'risk'` / `'cost'`）。40 格**全部**是 `risk` —— 定价被风险上界约束，不是被成本地板托底。这也是"我们不是在收手续费"的量化证据。

批量价：`P(N)` 直接按上式代入 `N` 求得，**不做二次折扣公式**；对外只发布 `batchDiscountBps[6]` 这一条折扣带（`N ≤ 1 : 0bps / 10 : 3878 / 50 : 4286 / 100 : 4286 / 500 : 4286 / 1000 : 4286`），合约按档查表，避免链上浮点。

### 1.3 关键假设（全部要能被打）

1. **概率来自 11 年 ERA5 再分析，不是预报**——`2015-10-01 ~ 2026-09-30`，五城逐小时，五城窗口数 96,421(12h) / 96,409(24h)。
2. **整数十分位口径**：所有毫米数放大 10 倍取整（`toDecimillimetres`）。理由：ERA5 是 0.1mm 十进制小数，`50.0mm` 恰为双精度可表示数，浮点累加会**单向漏计边界窗口**（广州 72h 实测漏 49 个：11153 / 11140 / 11134 三法只有放大取整是唯一确定解）。
3. **统计不确定性用月度块自举**（块长 = 1 日历月，4000 次），因为降雨有强季节性，逐窗 i.i.d. 抽样会低估方差。逐格边缘分位（全部格独立取分位）与联合自举（全部格同时重抽）**是两个不同口径**，数值不可互相替换：组合上界分别是 `0.60267%` 与 `0.517437%`。
4. **`E[f]` 是"赔付比例"不是"触发概率"**——概率有三个名字，不可混用：
   - `p₁` = 二元第一档触发率 = `nHit / nWin`（对外材料说"24h 无条件触发概率 0.4377%~1.4200%"用的是这个）
   - `E[f]` = 档位加权期望赔付比例 = `Σ(命中档位 × 该档赔付比例) / nWin`
   - `E[f]|timing` = 再按 κ 做月度择时加权 = 产物里的 `pointRatePct`，**定价用的就是它**
   - 武汉 12h 同格：`p₁ = 0.850437%`、`E[f] = 0.444924%`，差 **1.9 倍**。混用会直接把保费算高或算低一倍。
5. **本轮删掉 48h / 72h**：国标只有 12h / 24h 两个时段（§3 "降雨量按 12 h，24 h 两个时间段进行划分"），而国标自己两列的 `24h ÷ 12h` 比值为 `1.667 / 1.429 / 1.786`，**无一为 2** —— v2 的 `thresholdOf(h) = 50 × h / 24` 线性外推被国标自身证伪。删 72h 顺带消掉了 3 个不可售格（原 3 格全是 72h t0c0），现在 **40 格全部可售**。

## 三、正收益保障

### 3.1 判定条件

**每份保单的期望净收益**（保险人视角，一份一赔、赔付额 `PAYOUT_MAX`）：

```
margin = P − C(N,q) − q × PAYOUT_MAX  >  0
```

把 `q` 换成统计上界 `E_upper`（更严）：

```
margin_upper = P − C(N,q) − E_upper × PAYOUT_MAX  >  0
```

`margin > 0` ⟺ `P > 固定成本 + 期望赔付`。本文两个都算，**结论必须两个都为正**。

### 3.2 完整计算过程（解析，不依赖任何一格实测值）

`E_upper ≥ E[f] > 0`，且 `R* = 0.6 < 1`：

```
P  ≥ P_net = ceilTick( (E_upper·PAYOUT + C) / R* )
            ≥ (E_upper·PAYOUT + C) / R*
⇒ P − (E_upper·PAYOUT + C) ≥ (1/R* − 1) · (E_upper·PAYOUT + C)
                            = (1/0.6 − 1) · (E_upper·PAYOUT + C)
                            = 0.6667 · (E_upper·PAYOUT + C)  >  0
```

**同一条式子同时覆盖 `margin` 与 `margin_upper`**，因为 `E_upper ≥ E[f]` 时 `margin_upper ≤ margin`。
`1/R*` 与 `1 + M` 这两个 `> 1` 的因子是正收益的**结构性来源**：定价时在"上界赔付 + 固定成本"之上主动乘了一个大于 1 的系数，再把结果向上取整到网格。

**本轮的构造性验证**：对全部 40 格重算 `P = max(MIN_PREMIUM, ceilTick((E_upper·PAYOUT_MAX + C)/R*), ceilTick(C·(1+M)))`，与产物价对比，**最小余量 = `0.00011369 ETH/份` > 0**。

### 3.3 结论（实测 = 上式在真实数据上的取值）

| 指标 | 结果 |
|---|---|
| 40 格中期望净收益 ≤ 0 的格数 | **0** |
| 期望净收益区间（点估计 `E[f]`） | **`+0.00012710 ~ +0.00049702 ETH/份`** |
| 期望净收益区间（97.5% 上界赔付） | **`+0.00011369 ~ +0.00042143 ETH/份`** |
| 最脆弱格 | **北京 24h t2c1**：价 `0.00028`，固定成本 `0.00013027`，期望赔付 `0.00002263` → `+0.00012710` |
| 最赚格 | 武汉 24h t0c0：价 `0.00105` → `+0.00049702` |
| 每格 `boundBy` | **全部 `risk`**（风险上界主导，成本地板从未触顶） |
| 批量 N=1000 期望净收益 | `+0.00018718 ~ +0.00049702 ETH/份` |
| 每格 N=1 固定成本 | `0.00013027 ~ 0.00013502`（极差 3.6%），**全部远小于最低保费 0.00028** |

**结论：40 格全部为正，且按统计上界也全部为正。正收益不是"这一组数据碰巧"，是公式结构保证的。**

## 四、推导步骤 · 数值示例 · 敏感性分析

### 4.1 数值示例：北京 24h · `t2c1`（κ = 0，全表最脆弱格）

已知（全部取自 `pricing-engine.json`）：
`E[f]|timing = 0.226305%` → `q = 0.00226305`；`E_upper = 0.360409%` → `0.00360409`；`PAYOUT_MAX = 0.01`；`JUDGE_GAS = 0.00013`；`PAYOUT_GAS = 0.00012`；`R* = 0.6`；`M = 0.25`；`TICK = 0.00001`。

**第 1 步 固定成本** `C(N=1) = 0.00013/1 + 0.00012 × 0.00226305 = 0.00013 + 0.00000027 = 0.00013027`
**第 2 步 上界赔付** `E_upper × PAYOUT_MAX = 0.00360409 × 0.01 = 0.0000360409`
**第 3 步 风险腿** `P_net = ceilTick((0.0000360409 + 0.00013027)/0.6) = ceilTick(0.00027718483) = 0.00028`
**第 4 步 成本腿** `F = ceilTick(0.00013027 × 1.25) = ceilTick(0.0001628375) = 0.00017`
**第 5 步 取大** `raw = max(0.00028, 0.00017) = 0.00028` → `charged = max(0.00002, 0.00028) = 0.00028`（**`boundBy = risk`**）
**第 6 步 期望净收益**
`点估计：0.00028 − 0.00013027 − 0.00226305×0.01 = 0.00028 − 0.00013027 − 0.00002263 = +0.00012710`
`上界：0.00028 − 0.00013027 − 0.0000360409 = +0.00011369`
→ **两份口径皆为正。**

**批量对比（同一格，N=10）**：`C = 0.00013/10 + 0.00012×0.00226305 = 0.00001327`
`P_net = ceilTick((0.0000360409 + 0.00001327)/0.6) = ceilTick(0.00008218) = 0.00009`；`F = ceilTick(0.00001659) = 0.00002` → 价 `0.00009`，成本从 `0.00013027` 摊到 `0.00001327`（**9.8×**）。

### 4.2 敏感性分析

**(a) 赔付率 / 保费率冲击 —— 期望赔付放大多少倍才亏**

| 场景 | 转负所需放大倍数 |
|---|---|
| N=1 | **2.1× ~ 6.8×**（最脆弱：成都 24h t0c0，2.14×） |
| N=1000 | **2.1× ~ 12.6×** |

**对照**：全 40 格里 `E_upper ÷ E[f]` 的**最大比值只有 1.664×**（成都 24h t2c1）。
⇒ 即使真实概率一路取到统计上界（1.664×），距离"转负点"（≥2.1×）**仍有 26% 以上余量**。统计不确定性本身吃不掉正收益。

**(b) gas 冲击 —— 唯一能压垮最脆弱格的方向**

⚠️ **口径先说清**：`JUDGE_GAS` / `PAYOUT_GAS` = **gas 用量 × gas 单价**。用量取真链实测、与链无关；
单价取 **Sepolia** 2026-10-06（判定 1.080 / 赔付 2.500 gwei）。**换链必须重算** ——
`node margin_check.js` 现在直接按「用量 × 单价」逐档扫描单价，不再把系数乘在成本总额上。

| 赔付 gas 单价 | N=1 最小期望净收益 | 净收益 ≤ 0 的格数 |
|---|---|---|
| 2.5 gwei（本表口径，Sepolia） | `+0.00012710` ✅ | 0 / 40 |
| 5 gwei | `−0.00000320` ❌ | 2 / 40 |
| 10 gwei | `−0.00027374` ❌ | 37 / 40 |
| **20 gwei（BOT Chain 968 现网）** | `−0.00079487` ❌ | **40 / 40** |

- **N=1**：最脆弱的格在 **4.88 gwei** 就转负，到 **11.56 gwei** 全 40 格转负（最脆弱格 = 北京 24h t2c1）。
- **N=1000**：同一个转负点抬到 **292 ~ 1593 gwei**（最脆弱格 = 成都 24h t0c0）。

⇒ **结论必须分两层讲，不能只说一层**：
① **在 Sepolia 口径下**，gas 单价要涨到 **4.88 gwei 起**才让最脆弱的格转负（当前 2.5 gwei，1.95× 余量）；
② **换到 BOT Chain 968（20 gwei）这一层，40 格全部转负** —— 这不是定价公式的毛病，而是「微保险的固定成本被搬到了 gas 单价高 8 倍的链上」；
③ 同一个算式在 968 上仍然成立，靠的是**按份摊薄**：`JUDGE_GAS/N` 把判定那一笔摊开，N=1000 时转负点抬到 **292 gwei 以上**。
∴ 对外只能说「**经济性靠批量摊薄成立，不靠 L1**」，不能说「L1 上也成立」——与 `02-作战与答辩/外部PPT修订4-口径核对与并入建议-2026-10-07.md:28,34` 同口径。

另：gas 只影响成本腿（40 格 `boundBy` **全部是 `risk`**，见 §3），风险腿完全不受影响。

**(c) 目标赔付率 `R*`**

`margin ≥ (1/R* − 1)·(E_upper·PAYOUT + C)`。`R*` 是**唯一一个"调到 1 就归零"的参数**：

| `R*` | 结构性余量系数 `1/R* − 1` |
|---|---|
| 0.6（当前） | **0.6667×** |
| 0.8 | 0.25× |
| 0.95 | 0.0526× |
| 1.0 | **0（正收益失效，只剩取整余量）** |

⇒ **只要 `R* < 1`，正收益就是数学结论；`R*` 越大，靠的是取整与真实概率低于上界这两层缓冲。** 当前 0.6 留了 40% 缓冲，是有意保守。

**(d) 批量摊薄**

40 格中有 20 格（`channel=1`，平台代付）逐格计算 `C(1)/C(1000)`：**最小 83.7×、最大 325.7×、均值 177.7×**，门禁下界设 **80×**。
⚠️ 对外只能说「**逐格 84× ~ 326×**」。老文案里的「198×」是**其中一格**（武汉 12h 平台团体）的值；而「1000×」是**只算判定 gas 那一项**的摊薄，两个数不是一回事，混着说会被现场问穿。

### 4.3 一句话给评委

> 每份保费 = `max( ceilTick((97.5%上界赔付 + 固定成本) / 0.6), ceilTick(固定成本 × 1.25), 0.00002 )`。
> 分母 0.6 与乘数 1.25 都小于 1 / 大于 1，所以**保费天然大于"上界赔付 + 固定成本"**——40 格实测余量 `0.000114 ~ 0.000421 ETH/份`，全为正；即使真实概率再高 2.1 倍、gas 再涨 50%，仍为正。
