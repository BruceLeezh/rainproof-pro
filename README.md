# 雨证 Pro · RainProof

> **个人维护版本。** 项目源出「神麻」队汉客松 S1 & ETH Wuhan 2026 参赛作品，团队仓库为 [juice-butterfly/rainproof](https://github.com/juice-butterfly/rainproof)。本仓库是个人侧的工程与证据版本，独立演进，**与合作仓库内容不保证同步**。

## 是什么

**可验证的 AI 参数化配送险** —— 把「你信不信我」换成「你自己验」。

暴雨天配送是高频、小额、边界清晰的场景：骑手在雨里跑，收入受损。传统保险卡在两件事上——定损要人、赔付要等。参数化保险把触发条件写成代码：雨量达到阈值就赔，不需要报案、不需要查勘。

但"AI 自动判定"本身又是一个新的黑箱。所以本项目的重心不在模型多准，而在**每个结论都能被第三方独立复算**：

- 定价公式与系数表全部落在仓库里，不用问我们
- 触发判定读链上喂价，任何人可以自己去链上核
- 赔付金额由合约计算，不经过任何后台
- AI 判定过程留痕（`09-AI判定留痕/`），含输入快照与输出

核验台（`06-核验台单文件/`）是这个主张的实体化：零输入，8 条断言逐条自证，不需要相信任何人的说明。

## 本地跑起来

```bash
# 演示站点（纯静态，无构建）
python -m http.server 8090 --directory 05-演示站点
#   主入口  http://127.0.0.1:8090/index-v5.html
#   核验台  http://127.0.0.1:8090/verify-v5.html
#   骑手页  http://127.0.0.1:8090/rider.html
#   控制台  http://127.0.0.1:8090/console.html

# 喂价（需自备 .env，见 .env.example 口径）
node 04-脚本/push-rainfall-v5.js --send

# 门禁
cd 07-测试工具 && npm test
```

脚本需要 RPC 端点与签名密钥，均通过环境变量注入，仓库内不含任何密钥。合约已部署在测试网，只读验证不需要私钥。

## 设计取舍

**不要后端。** 三个静态页面直接读链上 RPC，省掉一层可信中介——如果数据要经过我的服务器，那"可验证"就打了折扣。

**喂价保鲜而非实时。** 天气 API 有配额与延迟，链上喂价带 `MAX_FEED_AGE`，超时则拒绝新保单成交。宁可少卖，不卖过期数据承保的保单。

**AI 只做辅助判定，不做最终裁决。** 模型输出落在留痕目录，链上赔付由合约按规则执行。模型错了，赔付逻辑不会跟着错。

**核验台优先于演示页。** 演示页是给人看的，核验台是给不信的人用的。后者才是这个项目的立论。
