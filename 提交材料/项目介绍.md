## 二、项目名称

**雨证 · RainProof** —— 可验证的 AI 参数化配送险。**我们卖的不是「保险」，是可验证的自动理赔。**

一句话：**用链下气象数据与写死的链上规则判定是否赔付；判定上链后任何人可调 `claim()`，钱只进保单登记的骑手地址。**

核心一句：**把「你信不信我」换成「你自己验」。**

## 三、目标用户

平台**众包骑手**：非雇员、按单计酬、没有底薪。

- **规模**：美团官方 2025-06-26 发布「300 万骑手免费上防暑险」—— **平台方一手口径**，须标明。
- **收入**：高频骑手月均 **7,230–10,100 元**（美团 2025Q1，经《工人日报》客户端）；一线城市**高频**熟练骑手月均 **11,547 元**（上海证券报·中国证券网 2025-03-22）。
  > ⚠️ **引用纪律**：这些数字只描述**高频骑手**，引用时必须带"高频"二字；三套公开口径互相冲突，**不可混用**（详见 `提交材料/用户与场景.md` §0）。
- **收入结构**：`R = 单量 × 单均`，没有底薪 —— **一天不能跑，收入就断**。
- **为什么天气是最关键的外生变量**：暴雨天平台会压缩配送时长、限制派单，骑手实际可跑单量骤降；而**意外险保的是"受伤"，不保"今天跑不了单"**。

**影响侧证据**（只用能打开的，且**只做描述、不做因果推断**）：

| 证据 | 数字 | 用途 |
|---|---|---|
| HBR 2024-11-27《When Gig Work Meets Extreme Weather》 | 沪杭 **1,272 名骑手 / 58 万单**：热浪日配送延迟率 **+21.8%**；每小时只多挣约 1 元，**两个月额外收入约 545 元 vs 健康成本约 501 元** | 「多劳不多得」最硬的量化证据 |

## 四、解决的问题

**定损成本与赔款同量级，所以这个人群没人保得动。**

| | 传统小额天气/收入中断险 | 雨证 |
|---|---|---|
| 谁来认定"事实发生了" | 人工查勘、平台流水核对、争议仲裁 | 公开气象数据 + 写死在合约里的规则 |
| 单笔定损成本 | 100–200 元量级（**行业量级判断，不是可引用的一手数据**，已如实标注） | AI 判定 gas ≈ **0.00013 ETH**，赔付 gas ≈ **0.00012 ETH**（Sepolia 2026-10-06 真链实测） |
| 一次赔付的周期 | 以周计 | 判定上链后，**任何人**调一次 `claim()` 即完成 |
| 争议在哪 | 「谁来认定事实」 | 没得吵：输入哈希 + 输出哈希都在链上，你自己复算 |

关键句：**传统的钱花在"查"，我们的钱花在"给"** —— 赔付额 ÷ 判定 gas ≈ **77 倍**；判定 + 赔付总成本 ≈ 赔付额的 **2.5%**。

> 口径：上面两个数是 gas **用量**（121,845 / 49,297，Sepolia 2026-10-06 真链实测）× 当时的 gas **单价**（1.080 / 2.500 gwei）。换一条链必须重算 —— 968 现网 20 gwei 下同样两笔 ≈ **0.0024369 / 0.00098594 BOT**（这项换算已如实披露，见 `提交材料/评委问答.md`）。

## 五、核心功能

一次完整的赔付旅程：

1. **投保** —— 骑手选城市 + 保障时长，现行 v3（主网 677）保费**按城市 × 12/24h 差异化 = 0.00053–0.00105 BOT（10 格）**（旧 968 测试网 v2 的 24/48/72 三档曾是 0.0004–0.0020 ETH，见下文括号注明）；合约把**投保时的累计降雨量封成基线** `rainfallAtBuy`，赔付**只看增量**（所以"已经下雨了再买"拿不到钱）。
2. **喂价** —— operator 把累计降雨、置信度、来源数、证据哈希写进链上。合约**真的会拒收**：`confidence >= MIN_CONFIDENCE (60)`、累计值单调不减、证据哈希非零。链下 `ai-collect.js` 同时取 ECMWF / GFS / ICON 三个数值预报模型交叉核验，离群就调 `rejectFeed()` —— **值不上链，异常留痕**。
3. **判定** —— `ai-judge.js` 用五条**确定性规则**算出 `PAY` / `DENY` 与置信度：
   - R1 链上官方增量 < 阈值 → DENY；
   - **R2 官方增量与三模型中位数背离 > 60% → DENY**（AI 最值钱的一条：第二个独立意见发现预言机在瞎写）；
   - R3 达标模型数 ≤ 1 → DENY；
   - R4 模型间离散度 ≥ 中位数 → 置信度压到门槛下 → DENY；
   - R5 以上都不命中 → PAY。

   判定结论（`decision` + `confidence`）与**输入证据哈希 / 输出结论哈希**写进链上事件，**链上不存原文**。LLM（DeepSeek）只写给人看的解释，且**解释不进哈希** —— 大模型输出跨版本不可复现，我们不拿它当证据。
4. **赔付** —— 三个条件同时满足才放款：链上期间增量 ≥ **合约的档线**（链上 v2 是 `50 × h / 24` 的线性外推：24 / 48 / 72h → **50 / 100 / 150 mm**；⚠️ **这不是"国标线"**，国标 GB/T 28592—2012 只有 12h / 24h 两档，见下方「时长为什么只有 12h / 24h」）、AI 判定 `decision = PAY`、置信度 ≥ **60**。
   实赔额按国标分档，取 `PAYOUT_MAX = 0.01 BOT`（v3 现行口径）的 **50% / 75% / 100%**（即 0.005 / 0.0075 / 0.01 BOT）。
   `claim()` **权限开放**：我们的 keeper 或任何第三方都能触发，但**钱只进保单里登记的骑手地址**。合约本身**没有**自动触发机制 —— 这句对外一定要说全。
   注意 `claim()` 要求 `block.timestamp <= endTime`：**一旦过了保单到期时刻就再也领不出**，所以判定必须在到期前提交。

**规则不可事后修改**：`PAYOUT_MAX = 0.01 BOT`（v3 现行；v2 时代写 0.01 ETH）、`THRESHOLD_PER_24H = 50 mm`（链上 v2 的 `thresholdOf(24/48/72)` = 50 / 100 / 150 mm，**线性外推、不是国标线**）、`MIN_HOURS`/`MAX_HOURS = 12 / 24`（现行 v3；链上 v2 尚存的是 24 / 48 / 72，v3 已删 48h/72h 外推档）、`REGION_COUNT = 5`、分档赔付比例（`tierOf` / `tierBps` = 50% / 75% / 100%，档**名**取国标暴雨 / 大暴雨 / 特大暴雨三级，但 v2 的档**线**是外推值）全是 `constant`，部署后连部署者自己也改不了。
operator 能改的**只有**承保价（`setUnderwriting` / `setPremiumGrid`）和 `coolingPeriod`、`eligibleRequired` 两个开关 —— **968 演示链上这两个开关分别是 `0` 和 `false`**（链上现值直接读，别背）。
保费**不是**常量：它是 operator 按精算报告提交的承保价，**每一次改动都留 `UnderwritingDecision` 事件 + 依据串哈希** —— 第三方可以复算出「这个价是怎么来的」，operator 决定写什么值，但写不出一个无法被复算的值。

### 诚实边界（主动讲，不等评委问）

1. **不判断骑手是否真的受损** —— 需要平台订单数据，拿不到；
2. **预言机目前是单一运营方在喂价** —— 我们的 AI 是给它第二个独立意见，不是替代它；
3. **准备金下限分版本说** —— v1 的守卫已实现（`withdrawPool` 不能击穿 `reserve`），但链上 `reserve` 靠人工设定；v2 已自动化成「未了结敞口」`reserveOf() = max(reserve, openExposure)`；
4. **链上保费的维度不全** —— 今天演示页与核验台读的是**主网 677 上的 v3**，它只喂了国标 12h / 24h × 五城 = **10 格**（`premiumOf(r, hours, 0, 0, 1)` 现场可验）；**968 上留痕的**才是 v2：**地区 × 时长 15 格逐格不同价**（24h 列多数格触到 0.0002 保费地板，所以短端看起来被压平，那是地板效应、不是同价；同价的只有更早的 v1）。缺的是**骑手类型 / 渠道 / 购买量**——所以"谁在买、买多少"不进价格。**v3 已把这三条算进价格，表已算好、参考合约已真编译核验，但 A 已回执赛期不动合约（v2 冻结）** —— 讲的时候请按"设计值"讲，别按"链上值"讲。补充：6h 档公平保费比它自己那笔链上手续费还便宜 51 倍，短档在 L1 上不成立，所以**链上 v2 只卖 24 / 48 / 72 三档**；**v3 按国标把时长收成 12h / 24h 两档**（§0：国标 §3 只定义这两个时段）。
