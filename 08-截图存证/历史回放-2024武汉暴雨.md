# 历史回放：2024-06-27 武汉暴雨 → AI 判定 PAY → 自动赔付

> 这份记录回答一个问题：**如果真下一场暴雨，这套东西会不会赔？**
> 答案是：用 2024 年真实发生过的数据，在链上跑了一遍，赔了 0.01 ETH。
> 全程 `simulated = false` —— 没有一个数字是编的。

---

## 一、为什么选这场雨

2020-07 武汉那场雨更大（3 天 391.0mm），但**用不了**：Open-Meteo 的历史数值预报归档
（`historical-forecast-api`）在 2020 年只有 `null`，三个模型的逐日序列取不到值，
AI 判定层的 R3（「至少 2 个模型独立支持」）就会把 PAY 拦掉。

2024 年及以后该接口有完整的三模型归档，所以回放选了 **2024-06-27 ~ 06-29 武汉**。
这不是挑软柿子 —— 它是近年真实的成灾暴雨，只是恰好有完整的多模型数据可复核。

## 六、这份回放真正的价值：修掉了一个「可复算」的假话

第一次跑通后，我用**同一份快照**又跑了一遍 `ai-judge.js`，结论一模一样（PAY 76），
但 `outputHash` 变了：`0x83ee374c…` → `0x984657d6…`。文件 SHA256 也跟着变。

原因：`04-脚本/ai-judge.js` 把 `decidedAt: new Date().toISOString()` 放进了**被哈希的
`judgement` 对象**里。采集侧 `ai-collect.js` 同样把 `collectedAt` 放进了 `snapshot` 里。

**这个 bug 直接推翻项目最核心的那句话** —— 「第三方拿同一份数据重跑，必然得到逐字节
相同的哈希」。链上写的是一个永远对不上的哈希，等于给评委看一个假证据。

修法（不碰冻结的 `canonical.js` 哈希口径，只挪字段）：
把易变字段搬到被哈希对象的**外面**，作为同一个 JSON 的兄弟字段。

```jsonc
// snapshot-policy<N>.json
{ "snapshot": { /* ...判定要用的全部内容... */ }, "collectedAt": "…", "inputHash": "0x…" }

// judgement-policy<N>.json
{ "judgement": { /* ...判定本身... */ },
  "decidedAt": "…", "rationale": "…", "rationaleSource": "deterministic", "outputHash": "0x…" }
```

`rationale` 也搬出去，理由是它**不参与决定**（项目口径：大模型只写措辞）。搬走之后，
即使日后接上大模型，判定哈希照样不受影响。

修复后实测（本文表格里的那组数字）：

```
第 1 次重跑 → outputHash 0xc132c7731cfcd5706dcba9b4e62b86addf4df10df74c309ad304a28acb454225
第 2 次重跑 → outputHash 0xc132c7731cfcd5706dcba9b4e62b86addf4df10df74c309ad304a28acb454225
两次文件的全部差异：只有 "decidedAt" 这一行（它故意不在哈希里）
```

`07-测试工具/check-ai.js` 已加上钉住它的断言（`decidedAt` 变 → 哈希不变；解释文字变 →
哈希不变；指标变 → 哈希必变），并且会**遍历 `09-AI判定留痕/` 下每一条留痕，当场重算
哈希**。这条检查已纳入 `npm test`。

> 遗留说明（诚实起见写在这里）：真链 Sepolia 上保单 #0/#1 的判定哈希是**这条修复之前**
> 写进链的，链上合约规定 `submitJudgement` 一份保单只写一次（`RainDeliveryInsurance.sol:214`），
> 所以那两条记录无法换成新口径。它们的 `outputHash` 按当时的完整对象（含 `decidedAt`）
> 计算，文件本身仍然自洽（`check-ai.js` 也会替它们验哈希）；**修复后的口径以本回放为准**。
